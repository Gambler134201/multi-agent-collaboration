# model-desk-dsh-brain

多agent协作的可选 DSH 原生主脑插件。只安装到 DSH **desktop 主脑 profile**，不安装到 DSH/Pi 执行器。

## 当前版本

本包是 **0.2.10 修复候选**：预检后在首次用户回复开头显示真实协作状态；右侧入口使用桌面可转发的 `/api` 精确路由，按需启动/复用工作台。连接服务通过 Cordis 原生注入后才注册入口，并随连接服务生命周期回收/重建。预检工具合并连接、身份、开关、范围和候选读取，新会话注入靠近当前输入的简短协作提醒。本包并不包含完整工作台后台，0.2.10 尚未安装或原生验收。

维护者此前原生验证使用 Windows、DSH `0.2.1-rc.2`、插件 0.2.6 加配套后台修复。正常单任务/两任务批次、完成后一次唤醒、受控失败通知、失败详情读取已验证。0.2.8 安装后的桌面入口返回 405；0.2.9 更正 `/api` 地址后返回 404，真实 Cordis 复现了未注入访问连接服务导致入口未注册。0.2.10 修正依赖注入，真实框架离线验证两种启动顺序、连接服务替换与卸载回收，不替换 Gateway 原有拦截器。首次回复信号与独立启动仍须原生实测，不把离线结果称为 GUI 通过。

首次发消息后，主脑应先真实预检，再在第一条可见回复开头显示 `user_signal.text`：绿色“多 Agent 协作已就绪”、灰色“协作已关闭”、黄色“已连接但没有可派发模型”或红色“协作未就绪”。关闭时只报告状态，不因这条提示启动服务或自动派发。绿色只确认连接、开关、责任绑定与候选，未实测模型接口，不是派发/验收成功。后续仅状态变化时提示。该展示由原生上下文规则要求模型执行，不是聊天输出的强制渲染拦截；插件完全未加载时也无法自行发出信号。没有看到提示，不应默认协作已正确加载。

## 功能与日常使用

1. 用户选择原生项目/聊天，插件据其实际会话绑定工作台；未知项目保持未绑定，不猜安装目录或最近项目。
2. 从原生右侧入口打开中文“模型工作台”。此次点击会由 DSH Host 按需启动或复用同安装目录的工作台，确认就绪后打开，不需要运行 Codex；导入插件和发现工具本身仍不启动服务。
3. 配置执行模型和每模型默认 Agent，打开“多 Agent 协作”，正常描述需求。主脑负责选型、决策和独立验收，执行模型负责调查、实现和测试。
4. 完成本批派发后调用一次 `brain_wait(action=start, task_ids=[全部原编号])`。只有 `waiting=true` 才说明已订阅并结束原轮次。
5. 全部任务结束后，本地等待进程向原聊天尝试一次固定通知。接收后登记 `received`，主脑独立检查，再分别验收。`completed`、通知接收和验收通过是不同状态。

协作开启时，新会话首次响应先 `brain_preflight`；后续新执行需求每轮一次。该工具可在原生启动配置允许时启动服务，不启动执行模型、不派发任务；读取结果中包含真实开关、范围、候选与归属。创作、文案、素材和文件生成也需要评估是否派发；简单一步、核心风险判断与独立验收允许主脑处理并说明理由。关闭协作时不注入自动派发提醒，也不全局拦截普通 write/bash 工具。

等待阶段不调用主脑模型；派发、完成唤醒及验收会产生主脑用量，执行模型也可能收费。关闭聊天、退出/重启 DSH 或操作系统休眠后的通知恢复没有原生保证。未知投递不自动重发或重派；停止通知不取消任务。

顶部 DSH 余额来自官方登录账户接口的公开快照，通常约两分钟更新一次；与工作台执行模型 API Key 的账户独立，不假定额度互通。失联/过期应显示未知，不读取认证文件补齐余额。

## 安装方式

需要包含本包和匹配后台的完整多agent协作工作台。完整源码里的 `docs/DSH_USAGE.md` 提供安装、升级、卸载命令；`docs/DSH_RELEASE.md` 给出配套版本与验收边界。在源码中它们位于本目录上两级的 `docs/`；独立 tgz 不包含这些源码文档。

由工作台的 `.local-worker/dsh_brain_desktop.py` 按显式工作台、Python、DSH 可执行文件与 `DSH_HOME` 准备安装资料，再分别执行 `check`、`install`。安装前等待执行任务结束、完全退出 DSH；安装器不会替用户关闭或重启应用。

`prepare` 写一个新的、专属本机安装资料目录；`check` 连接已运行的工作台做无任务变更权限的预检。`install` / `uninstall` 才调用官方 desktop 包管理命令并维护自己的环境值。已有同名插件不被收养或覆盖；升级先使用原资料目录的收据卸载，再在新目录准备和安装。

准备目录里的 `plan.json`、`config.json`、`plugin.tgz`、安装后的 `receipt.json` 都需保留，不能当临时缓存删除，也不应随公开发布分享。后台源码或 DSH 安装改变后，旧计划的指纹可能失效；重新准备，不能改旧计划/收据冒充匹配。

没有设置内联配置时，插件从 `MODEL_DESK_DSH_BRAIN_CONFIG` 读取唯一的本机 JSON 配置路径。安装器维护这一条 User 环境值；配置缺失时保持未启用，不猜项目或路径。公开包不含用户配置、账号或密钥。

| 文件 | 用途 |
| --- | --- |
| `package.json` | 包身份、版本及 Host/Client 声明 |

| `account.cjs` | 官方登录账户余额快照 |

| `cordis.patch.yml` | desktop 插件条目 |

安装器把唯一的客户端来源标记替换成 Host 配置的同一回环 `panelUrl`。自定义端口必须重新准备；不能只改 live config，造成界面与工具连接不同后台。

## 权限与异常

项目、原生聊天和角色来自宿主绑定，工具参数不能改 owner/project。子 Agent 和执行器不获得主脑派发/验收权限。插件每次派发、整改前重读协作开关；关闭不取消旧任务。

模型范围、模型保存的执行 Agent、付费授权及预算门禁仍由共同后台执行。同项目历史可以只读，不能据此验收、整改、接管别的 owner 的任务。工具参数防护和记录隔离是应用层机制，不是 OS 沙箱。

任务失败后保留原错误和未验收状态；新后台在 status/delivery 返回 `execution_error`，status 还保留兼容 `error`。读取失败不等于任务成功，结果未知不换 request_id 重派。原生取消/待恢复、未知投递、重启/休眠及跨工作区的行为仍需各自验证。

本包 MIT；DSH、Pi、Codex 和其他第三方运行时由用户自行安装并遵守其许可。仓库默认不执行 npm 发布，候选包准备不等于已公开上线。
