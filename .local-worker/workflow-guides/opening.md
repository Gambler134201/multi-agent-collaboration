# Opening and project identity

Explicit requests to open/view the workbench or start its service use `@ROOT@\打开模型工作台.ps1` with native pwsh and -NoBrowser, even when collaboration is off. Verify readiness; view requests use open_in_codex at http://127.0.0.1:8765/. Preserve settings; never dispatch a worker just to open the panel. The global model_desk MCP exposes the same workbench in all local projects; no native Codex button is claimed, and native UI visibility requires actual human verification. Project views are request-local: each project's own history lives in that project's `.model-desk` directory (`records.db` plus `runs/<task_id>`, where `task.json` is the content authority), and the global `project-index.json` only locates ids, so never treat the index or a global last-project as the record owner. When the calling project absolute directory is actually known, bind browser opens with a URL-encoded ?project= parameter or supply the MCP opener project argument; when it is missing, untrusted or ambiguous, leave the panel unselected and let the human choose a directory inside the panel. Never use the service installation directory or a different tab's last project. Exclude `.model-desk` from default code search and index scans (a default exclusion, not an OS-level sandbox; full-access executors may still read it). All-projects is an explicit view only, while model settings/account quota/day budget remain global. Do not initialize Git to enable a project button.

## Local integration

Every local project also reaches the workbench through the globally registered MCP server `model_desk` (see `README.md`, section 全局入口（MCP Apps）). Its `open_model_desk` tool declares the MCP Apps global and thread entrypoints and serves the workbench UI from resource `ui://model-desk/workbench-v1`; the UI proxies panel calls through the host tool `panel_request` and the real session token stays inside the MCP process. The panel service starts only on an explicit open or first session request, a running service is reused, and importing or listing the MCP server never starts it. Native entry buttons inside the app still require human verification; project environment-bar buttons remain Git-dependent and must not be enabled by initializing a repository.
