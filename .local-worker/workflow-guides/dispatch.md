# Routing and dispatch

Respect the global workflow `model_scope` (`all`, `paid_only`, `local_only`) before choosing eligible candidates. Only `provider=local` belongs to local/self-hosted; other providers are paid. Never cross this scope for manual/default selection, preview, stage, continuation, rework or recovery. No qualified candidate means refusal, not a fallback. Existing paid authorization and capability/budget gates remain independent. Legacy absent scope defaults to all; invalid scope refuses execution.

When `enabled=true`, Codex plans and independently reviews; use the saved Model Desk execution Agent (DSH or Pi) for suitable scoped execution tasks. User/project permissions and instructions still apply. Start `@ROOT@\启动模型面板.ps1` if the enabled workflow needs its service. Read public model presets with `@ROOT@\.local-worker\venv\Scripts\python.exe @ROOT@\.local-worker\run_worker.py --list-models`; do not read or expose secrets. Treat abilities as user declarations, not proven quality scores. Assess capability_notes and preferred_tasks; write a small UTF-8 task file and routing JSON containing category, complexity, estimated input/output tokens, expected_calls, eligible_model_ids, assessment, and acceptance. Only include models you judge capable; input_tokens must include relevant files and tool/history space, not just the task text. Do not send the whole main chat.

Use outcome ownership, with approximately 30% core responsibilities for Codex: clarify needs, make consequential decisions, judge capability/risk, choose a worker, and independently accept results. Make only the minimum orientation reads before dispatch. Give the worker the goal, allowed scope, constraints, decidable acceptance conditions, and relevant context; let it investigate, design, implement, test and correct autonomously. Do not investigate and solve the full task first, send a ready-made patch, or split every small edit into a fresh delegation. Ask workers to batch independent reads and avoid repeated broad searches. Trivial one-step tasks and core high-risk decisions may stay with Codex. This is a responsibility target, not a measured token ratio; never fabricate a savings percentage.

Dispatch from the actual calling project directory with `@ROOT@\.local-worker\venv\Scripts\python.exe @ROOT@\.local-worker\dispatch_task.py --route auto --kind edit --project <absolute-project> --files <scoped-files> --task-file <UTF8-task> --routing-file <UTF8-JSON> --notify-on-completion` on the verified local desktop. Read `waiting.md` for confirmed startup, batch subscriptions, receipt and independent acceptance. An unavailable bridge is rejected before dispatch; use quiet `--wait` instead when necessary. A listener startup failure after a successful submission preserves the original task and must not cause a second submission. Use `--kind chat` for read-only analysis, and `--preview` (without notification/wait flags) to inspect routing without inference. The backend enforces enabled state, declared complexity/context/output limits and configured paid budgets. Do not bypass a rejection by silently selecting a different model/engine. If no worker qualifies, explain and reconsider task scope. Paid execution requires the panel's paid_allowed; money caps apply only when enforce_paid_budget=true; never silently switch to a paid provider. Do not automatically retry a failed task more than once. On a corrective retry or upgrade, mark failed_model_ids or reassess explicit candidates, and record the reason.

Continue a finished DSH or Pi session manually with --continue-task <id>; it preserves model/project/files and runs as a new record. --reuse-session is the explicit exception; the default for new tasks and corrective rounds is a fresh session. To change models, start a new task. Model Desk status "completed" is executor completion, not proof of correctness: inspect real changes and appropriate tests, then report verification. Re-read the switch before each new automatic dispatch; turning it off does not cancel already-running jobs and does not dispatch new stages. This is a local instruction integration plus an MCP Apps entrypoint for this machine's local projects, not a built-in Codex mode or native subagent mode, and not a cloud/remote-host-wide setting. Existing chats may need a fresh session to load these rules.

## Project configuration

First read `.local-worker/workflow_settings.py --status` with the venv Python at the start of every user turn. If enabled is false, missing, or unreadable, use ordinary Codex behavior and do not automatically dispatch to this panel or start its service. Explicit worker requests remain allowed. If enabled is true, Codex plans, dispatches suitable scoped work through the saved execution Agent, and independently reviews actual changes and verification. Aider is available only when explicitly selected; do not silently switch execution engines or models.

Settings are in `@ROOT@\.local-worker\settings.json`. Use `--status` to check connectivity. Long prompts belong in a UTF-8 task file; do not interpolate shell-sensitive task text into command strings. Pass only the relevant files. For new projects, read their applicable AGENTS.md before dispatching work. This launcher is not a sandbox; review all actual file changes.

The model panel is at `http://127.0.0.1:8765`. Start it when the enabled workflow or an explicit manual request needs it. Model connections and the manual default worker live in `.local-worker/models.json`; manage them in the panel. `settings.json` is only the migration source. List public models with `run_worker.py --list-models`, or read `/api/state`. No model ID defaults to automatic routing (requires enabled=true); --route manual uses the manual default, while --model-id explicitly selects a model. Never expose stored keys. All dispatcher calls share the sequential queue and visible history.

Add `--test-cmd` only for an explicit appropriate project test command. Do not infer successful testing from an Aider exit code. Read the compact returned result and relevant changes; read full logs only when necessary. On failure, diagnose the cause and at most retry the scoped worker once before handling or reporting the issue. Do not silently switch to a paid provider.

## Execution Agent selection

`workflow_settings.py --status` reports the global `execution_agent` (`dsh` / `pi`, older settings default to DSH). A model may save `default_agent` as `dsh`, `pi`, or `follow_global` (missing legacy values inherit). Omit `--engine` for new tasks: precedence is deliberate task override > selected model default > global default. `--engine dsh` / `--engine pi` override only that task. Automatic model routing resolves this order for each final candidate and checks that actual Agent's readiness; unavailable/invalid preferences never silently switch engines. The collaboration bar's per-model model/Agent/save shortcut and the model editor's “默认执行 Agent” decide who executes; “各执行 Agent 参数设置” only controls adapter-specific presets. The global-default selector is removed from the UI; the stored global fallback remains compatible and unchanged. Queued/running tasks keep their recorded engine; continuation, corrective work and explicit session reuse keep the original engine/model/project/scope, with a fresh corrective session by default. Pi uses the locally verified 1.3.0 RPC transport with isolated task-owned configuration, the same provider/accounting relay and the shared `.model-desk` tool-argument guard. It does not import user Pi auth, discovered extensions/MCP, DSH presets or subagent grants. No OS sandbox is claimed. Native menu visibility still needs human verification.
