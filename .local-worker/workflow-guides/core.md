# Optional Model Desk collaboration

At the start of each user turn, before substantial work, run `@ROOT@\.local-worker\venv\Scripts\python.exe @ROOT@\.local-worker\workflow_settings.py --status` without starting a service. Missing/unreadable settings, launcher or `enabled=false`: ordinary Codex behavior; no automatic worker dispatch/service start. Explicit requests to run a named worker or open the panel remain allowed. Re-read the switch before every automatic dispatch; turning it off never cancels running work. Preserve user settings and permissions.

When enabled, use the user-selected execution Agent (`execution_agent`: DSH or Pi) for suitable scoped execution. Omit `--engine` to honor that saved default; an explicit engine is only for a deliberate task override. Changing the default never switches a queued/running task or its continued/rework session; Pi does not load DSH presets or nested agents. Codex owns clarification, consequential decisions, capability/risk assessment, routing and independent acceptance; workers own investigation, design, implementation, tests and correction. Orient minimally before dispatch; send goal, scope, constraints and decidable acceptance, not a solved patch or the entire chat. Keep trivial single-step tasks and core high-risk decisions with Codex. The approximate 30% responsibility target is not a measured token quota or savings rate.

Quality first: retain uncertain requirements and high-impact decisions with Codex. Assess public capability_notes/preferred_tasks as declarations, never proven scores; include only judged-capable candidates. Estimate input with relevant files/history/tools. No silent model/engine/provider substitution, budget bypass, or automatic retry beyond one corrective round. Paid execution requires paid_allowed; enforce_paid_budget=false and enforce_model_call_limit=false disable those optional ceilings. Never re-enable/raise limits silently. Total runtime defaults to timeout=0; silence does not justify cancellation or a deadline. Never read/expose secrets.

Only after a local desktop completion-path diagnostic has passed, prefer `--notify-on-completion` with the trusted calling project and read `@ROOT@\.local-worker\workflow-guides\waiting.md`. Announce waiting only after listener startup is confirmed; end the turn, let the hidden local watcher wait, and independently review after its one completion message. Batch tasks before subscribing; do not arm overlapping batches. Clearly distinguish waiting, execution ended/reviewing, accepted/completed and attention. Other hosts or an unavailable bridge use quiet `--wait`; `--progress` only for requested progress or diagnosis. Resume that same session/cell with bounded waits up to 60 seconds, batching tool-only waits. Do not repeatedly inspect records/logs/source or duplicate investigation. A lost waiter attaches with `dispatch_task.py --wait-task <original-id>` without dispatch. Unknown notification never permits automatic resend or redispatch; no blanket zero-usage promise.

Executor `completed` is not acceptance. Inspect actual relevant changes (edit scope is not an OS sandbox), run minimal meaningful independent checks and require independent evidence for every criterion. Self-reports are claims. Record acceptance via review_task.py; preserve raw executor failure on main takeover with --final-accept. At most one automatic rework; after another failure record --block and decide escalation. Records are local workflow evidence, not cryptographic proof or automatic correctness.

Project identity must come from the trusted calling project absolute directory. Bind panel opens using URL-encoded ?project= or the MCP project argument; unknown/ambiguous identity stays unselected. Never infer it from the service directory or another tab's last project. Each project's `.model-desk/records.db` and `runs/<id>/task.json` own its history; global project-index.json is only a locator. Exclude `.model-desk` from default search/index scans (not an OS sandbox). All-projects is explicit; models/account quota/day budget remain global. Never initialize Git for a button. Native entrypoint visibility requires human verification.

Stages may dispatch only after prerequisite independent acceptance. Required handovers must verify real file hashes, task/stage identity, same project/goal and real dependency; missing/stale references block dispatch. Cancelled stages/goals stay cancelled; completed/cancelled goals cannot dispatch. Recovery_pending is never silently re-sent. Each stage/new task/rework starts a fresh session in the selected execution Agent unless --reuse-session is explicit. Existing valid mechanisms remain authoritative.

Execution models must not write, edit, delete or move `.model-desk` records or place business artifacts there; only workbench controller code maintains task/log/acceptance/handover records. Never evade a tool refusal through another tool, script or provider. DSH and Pi apply a verified tool-argument guard, not OS-level isolation; arbitrary script targets remain a documented limitation. Keep normal controller writes and records in the owning project.

No nested delegation unless all three gates pass: independently measured exact model/executor/preset/version identity, explicit user policy, and expected benefit for this task. Home/local never gets a child; unknown/stale/unmeasured modes stay denied. Paid does not imply capable; default allow is not task authorization. Child cost is only part of DSH aggregate usage, never a separately measured invoice.

Read only the operation-specific guide before performing that operation (absolute paths below; these documents contain mandatory details):
- For nontrivial work, read `@ROOT@\.local-worker\workflow-guides\efficiency.md` once as needed: select acceptance-plan before dispatch/review, consume the waiter's delivery packet once after return, use verified stage-context to resume, and request calibration only when reassessing routing. Avoid redundant helper calls; these aids never approve work or replace GPT judgement or authorization.
- Routing/dispatch/continuation: `@ROOT@\.local-worker\workflow-guides\dispatch.md` and `limits.md` in that directory. Include task-level acceptance and concentrate waiting as above.
- Acceptance/rework/takeover: `@ROOT@\.local-worker\workflow-guides\review.md`.
- Stage creation/dispatch/recovery/handovers: `@ROOT@\.local-worker\workflow-guides\stages.md`.
- Any nested delegation: `@ROOT@\.local-worker\workflow-guides\delegation.md`.
- Explicit panel open/start: `@ROOT@\.local-worker\workflow-guides\opening.md`; native pwsh launcher with -NoBrowser, verify readiness, open_in_codex for view requests, preserve settings, no worker just to open.

This is a local workflow integration and global model_desk MCP entrypoint, not a native Codex collaboration mode or a cloud-wide setting. Existing chats may need a fresh session to load changed instructions.
