# Nested delegation gates

Optional nested delegation (one in-process child level) stays disabled unless three independent gates all pass: same-identity measured capability, explicit user policy, and a real expected benefit for this task. Capability, permission and task value are separate facts; paid does not imply capable, and a default `allow` never turns an ordinary request into delegation. A capability claim only counts for the exact `model + executor + agent preset + version` identity the main brain independently accepted; a changed version, an unknown mode or an unmeasured model stays denied, and the local `/` home model never gets a child. Currently only the DeepSeek `deepseek-flash` identity (preset revision `b8568f10…`) has main-accepted measured coverage for `chat` and `edit`. DSH provides no per-child invoice, so child usage is only part of the parent's aggregate; never present a per-child cost as measured. Full-access `edit` scope is a permission/prompt scope, not an OS-level hard file isolation — review every actual change. Treat user-declared capability prose as declarations, not as enforced access limits.
