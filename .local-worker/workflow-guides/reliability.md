# Transient-fault recovery and bounded retry

Recovering a transient fault must never lower acceptance. Diagnostics are historical facts: keep them, and decide the outcome from *current* evidence.

- Outcome attribution: a task record carries an append-only `fault_events` list (schema 1) with a safe category, fault class (hard/transient/unknown), optional HTTP status and a compact label - never a provider body, prompt, key or raw exception text. An entry is `resolved` only when a later request through the same relay actually delivered a response. A completed, valid executor result must not fail because a resolved transient entry (or the legacy `budget_error`/`gateway_error` mirror) is still present; an unresolved entry of any class, and records with only the legacy fields, still fail. Hard categories (auth, paid, protocol, identity, cancelled/policy) are never auto-resolved.
- Home metadata probe: at most two attempts, 30 s read timeout each, bounded interruptible delay; an exact model mismatch is fatal and never retried. If metadata is unavailable, a `thinking_level=default` task continues on the engine default with no injected thinking control and records degraded/unknown evidence (never "freshly verified"). An explicitly chosen non-default level may only use identity-matched, verified metadata - a cache is usable only within 1 hour and is labelled. User presets and shared engine settings are never changed by a probe; only the engine metadata cache may be refreshed.
- Relay transport: the upstream socket waiting allowance is 300 s and is a transport bound, not a task deadline (task timeout 0 stays unlimited). At most one automatic retry per logical request, and only for a provably unaccepted connect-phase or explicitly rejected failure with nothing delivered to the caller: no retry after a response/stream byte was delivered, never on an uncertain timeout, no whole-job re-dispatch and no provider/model substitution. Retry-After is honoured only when bounded (cap 10 s); cancellation stops the backoff. One logical request keeps one reservation and one ledger receipt; the extra attempt is recorded as `transport_retries`.
- Exit grace: after both executor streams close, wait up to 30 s for the process to exit; a real validated outcome survives a slow teardown (`exit_grace_exhausted` is evidence, not a failure), and a real executor failure is still reported as failed.
- Restart recovery: queued tasks that never started and running tasks whose recorded worker is genuinely gone become `recovery_pending`/待恢复 - never a blanket failure and never an automatic re-send. The original task, model, project, scope, session and progress stay; only an explicit, confirmed `POST /api/tasks/<id>/recover` resumes the *same* record (no new record, no auto-acceptance) after the dead worker is verified gone. Stage cancellation, acceptance, dependency and hash checks stay authoritative.
- Stale connectivity: an old failed connection check no longer permanently excludes a model. The router's verdict is pure (no I/O); a fresh failed generation test still blocks automatic routing, a failed read-only reachability check never becomes a capability verdict. Before a real dispatch, one bounded read-only `GET /models` recheck may establish reachability - labelled `kind=reachability, inference=false`; it never performs generation, never bypasses model/paid/complexity/identity gates, and route preview stays free of inference and network side effects.
