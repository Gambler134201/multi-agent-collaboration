# Independent acceptance and rework

For new records, executor completion is still pending while `controller_finalization.state=pending`; do not accept, rework or create handovers until settlement. Attention keeps its exact error and occupied resources. The original brain owner may explicitly call `brain_finalize` with a fresh request_id to verify controller-only cleanup; it never sends a model prompt or retries execution, and unknown live/native state refuses. Already settled/accepted results cannot be recommitted through this operation. Preserve raw interrupted/failed status when recording main takeover.

After independently accepting a batch, `brain_integrate(request_id, task_ids, checks)` merges only frozen accepted commits and runs the supplied command argument arrays in an isolated integration copy. Keep the copy and inspect the evidence; passed checks are not automatic integration acceptance or permission to overwrite the user's tree. On a lost/unknown response, query the original request_id with `brain_request_status`; do not reissue the effect. Missing/stale worktrees or unconfirmed settlement block handovers and integration.

When the installed toolset supports `brain_accept_integration`, independently inspect and test the kept integration copy, then call it with a separate `request_id`, the returned integration `name` and per-criterion independent `criteria`. It rechecks frozen inputs and the copy, records the accepted commit for existing downstream baseline selection, and never runs models/checks or writes the original tree. Query an unknown original request; do not create a new acceptance id as a retry. Older installed toolsets do not acquire this operation merely by updating a guide.

Keep review compact and independent. Read the worker's deliverable and actual relevant changes, run the smallest meaningful independent checks, and expand only for a concrete unresolved concern. Use `@ROOT@\.local-worker\venv\Scripts\python.exe @ROOT@\.local-worker\review_task.py --task <id>` to inspect the acceptance record. Record --accept with --evidence-file <UTF8-JSON> and independent evidence for each criterion; executor self-report is insufficient. Acceptance may be given as a string or a canonical array; an array is kept as one condition per element. For a failed criterion use --return-rework with --failed-criteria, --problems and --boundaries, then dispatch_task.py --rework-of <id> (same model/project/files, at most once). Send observations and acceptance gaps rather than the complete repair solution. A corrective round starts a new DSH session by default and carries the previous deliverable, the failure evidence and the correction scope; only --reuse-session explicitly reuses the old session. When the executor did not complete and the main brain takes over, record the independent result with `review_task.py --task <id> --final-accept --evidence-file <UTF8-JSON> --notes <what you did>`; that keeps the executor failure and the rework count and never fakes executor completion. After another failed attempt, record --block with a reason and decide escalation or core intervention. Review records are local workflow evidence, not cryptographic proof of actor identity or automatic correctness.
