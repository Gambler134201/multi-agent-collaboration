# Independent acceptance and rework

Keep review compact and independent. Read the worker's deliverable and actual relevant changes, run the smallest meaningful independent checks, and expand only for a concrete unresolved concern. Use `@ROOT@\.local-worker\venv\Scripts\python.exe @ROOT@\.local-worker\review_task.py --task <id>` to inspect the acceptance record. Record --accept with --evidence-file <UTF8-JSON> and independent evidence for each criterion; executor self-report is insufficient. Acceptance may be given as a string or a canonical array; an array is kept as one condition per element. For a failed criterion use --return-rework with --failed-criteria, --problems and --boundaries, then dispatch_task.py --rework-of <id> (same model/project/files, at most once). Send observations and acceptance gaps rather than the complete repair solution. A corrective round starts a new DSH session by default and carries the previous deliverable, the failure evidence and the correction scope; only --reuse-session explicitly reuses the old session. When the executor did not complete and the main brain takes over, record the independent result with `review_task.py --task <id> --final-accept --evidence-file <UTF8-JSON> --notes <what you did>`; that keeps the executor failure and the rework count and never fakes executor completion. After another failed attempt, record --block with a reason and decide escalation or core intervention. Review records are local workflow evidence, not cryptographic proof of actor identity or automatic correctness.
