## 2. A：派发结果确认与原请求找回

**来源：**Temporal 的幂等原则、LangGraph 的持久进度思想，以及本项目收据故障模拟。

实施内容：

1. 审查“保留请求 → 创建任务 → 保存收据”的所有异常出口，包括最终 `complete()` 写入失败，确保操作可能发生后不误报确定拒绝。
2. 为可证明的前置拒绝、请求处理中、结果未知和已确认任务保留不同返回含义。不能单靠 HTTP 400/500 或中文错误推断有没有产生副作用。
3. 已新增正式只读请求查询 `brain_request_status(request_id)`，范围限定到当前可信项目和 owner/binding，不能凭引用读取其他项目。
4. 可唯一匹配实际任务时返回 task_id 和原始状态；无记录不等于“肯定未执行”，多个匹配、记录不完整或仍处理时明确保留不确定性。
5. 需要修补收据时另设显式、审计可追溯的恢复操作；只读查询不偷偷写日志终态。既有 unknown 不自动再次调用模型，不换 request_id 绕过。

验收标准：

- 使用临时数据库与 mock 操作：操作成功、收据写入失败时，客户端收到 unknown 和原请求引用，不能收到“确定拒绝”。
- 相同 request_id/相同参数重复请求不会重复执行；参数变化明确冲突。
- 查询仅返回归属合法的原请求，跨项目、跨 owner、损坏/歧义记录不泄露内容。
- 模拟请求保留前失败、操作前明确拒绝、操作后响应丢失、控制器重启、查询中原请求仍运行。
- 所有场景的模型调用次数由 mock 计数验证，未知结果不得产生额外调用。

## 3. B：统一结果结构与错误来源

**来源：**CrewAI 任务契约、OpenHands 工具事件、A2A 终态区分；字段定义由本项目自行设计。

建议采用带 `schema_version` 的公共结果，至少区分：

| 维度 | 含义 |
| --- | --- |
| 请求结果 | 是否明确创建、拒绝、处理中或未知 |
| 执行状态 | queued/running/completed/failed/cancelled/recovery_pending 等现有状态 |
| 制品 | 实际交付文件与可核验版本，不能只读执行器自述 |
| 验证 | 未运行、通过、失败或未知；执行器自测与主脑独立证据分开 |
| 权限 | 稳定规则编号、动作类别、脱敏目标信息和证据来源 |
| 收尾 | 原生会话关闭、非必要临时清理的各自结果 |
| 主脑验收 | 尚未验收、退回、独立通过或主脑接手后的最终通过 |

先把稳定错误码作为事实，中文文案作为展示。旧任务缺少字段时显示 legacy/unknown，不根据关键词补造“已验证”来源。质量统计区分：端到端独立通过率、可判定质量样本通过率、系统故障率、未知占比；系统故障不能从所有指标里悄悄消失，主脑接手不算执行模型独立成功。

验收标准：

- “权限管理功能测试失败”“预算计算逻辑错误”这类业务失败不因关键词自动算成已核实系统故障。
- 原生权限拒绝、余额不足、DNS 故障等有真实结构化来源时能准确归类。
- 文件已生成但验证/会话关闭失败，仍保留原始失败，并能显示制品与失败阶段；不会自动接受成果。
- Pi、DSH、WorkBuddy 的公共字段含义一致；旧记录可读；修改文案不改变规则编号。

## 4. C：适配契约、能力目录与 doctor

**来源：**Agent Orchestrator 的适配能力目录、Microsoft Agent Framework 的执行器边界与 ACP。

建议将执行端适配拆成：安装/通道探测、任务准备、会话创建、执行/工具事件、交付收集、取消、恢复、关闭。每项能力独立声明，不支持明确返回原因。公共控制器保留项目身份、开关、请求去重、范围、预算、阶段依赖和独立验收。

能力目录应展示版本与证据时间：文件读写、终端、自测、原生模型选择、账号来源、取消、续接、嵌套委派。声明能力与实测证据分别显示；不得把“进程存在”“列出了模型”当作模型调用成功。

离线 doctor 只读检查依赖、路径、服务/通道、配置结构和绑定，不启动服务、测试推理或读取认证文件。在线模型验证独立命名并记录授权和费用边界。预检能发现问题，也必须在正式派发前重新权威校验。

验收标准：

- 新增最小 mock 执行端时，不需要在控制器多处添加同名分支才能完成公共契约测试。
- 三个执行端分别覆盖可用、未安装、版本不匹配、通道未就绪、权限不足和未知状态。
- 默认模型/Agent、旧任务会话及已排队任务快照保持原值，不能因重构静默切换。
- Codex、DSH 共用公共接口测试；原生入口、余额、首轮信号及唤醒另列真实宿主验收，不用 mock 结果代替。

## 5. D：诊断包、回放与验收时版本

**来源：**Raven 轨迹回放、LangGraph checkpoint、MetaGPT 制品交接思想。

第一版仅采集控制器本来持有且与本任务相关的最小字段：代码/适配器版本、归属、脱敏任务配置、规范化事件、规则编号、阶段、制品摘要与哈希、独立测试结果、验收条件和结论。不要读取宿主认证或复制完整聊天；原始包和可分享包分开，分享前有预览，默认不上传、不入 Git。

以录制的 mock 返回进行离线回放，禁止执行录制的 Bash/PowerShell、文件写入、网络调用或模型请求。缺少原始事件时标记不可回放。回放一致只证明控制逻辑与记录一致，不证明答案正确、性能提高或新模型适合任务。

接受成果时保存相关文件清单、内容哈希、基线/提交（若有）、测试环境和证据版本。以后文件改变时显示“历史验收通过，当前制品已变化”，不抹掉旧验收，也不将旧通过延续到新内容。

验收标准：

- 用人工植入的假密钥/私人路径检测脱敏；测试不接触真实密钥。
- 回放中 mock 模型、外部命令和副作用调用计数为零。
- 对路径逃逸、损坏哈希、缺少记录、不同版本、不匹配项目明确拒绝或标记不兼容。
- 验收后改动制品能显示陈旧证据，阶段依赖继续遵守已有哈希交接规则。

## 6. E/F：有限并行与受控集成

**来源：**Agent Orchestrator 的任务工作区、LangGraph 的分步恢复；执行步骤以现有并行计划为主。

任务先带目标、接口、依赖、资源范围和验收标准，再决定可否并行。初版每个模型最多一项任务，重复别名、共享推理服务/账号/原生会话不能当作独立并发资源；启用卡片数量只是候选上限，不是必须启动的数量。

Git 项目从明确基线创建任务 worktree，在独立集成区试合并并运行集成检查；无 Git 或无法确定基线先串行，不自动 Git 初始化。代码执行目录与原项目记录归属分开，通知仍回原责任聊天。

另管理临时目录、浏览器 profile、端口、测试数据和外部服务占用。独立 worktree 不会自动解决语义冲突；同文件可合并也可能接口不兼容。清理前展示工作区归属、未提交成果和保留原因，不能强制删除脏工作区。

预算限制开启时需原子预约与结算；用户关闭可选上限时维持关闭，未知费用明确保留未知。批次订阅一次完成通知，逐项独立验收，再做集成验收。取消一个任务不自动取消其他任务；失败或未知不重派整批。

验收标准：

- 用可控 mock 证明独立任务时间区间重叠，共享资源任务排队，不以“都已派发”冒充并行。
- 用户未提交改动保留；文件冲突和接口冲突都能阻止错误集成。
- 服务重启、取消、原生任务失败不重复调用、不错误释放其他任务资源。
- 两个任务完成前后的不同顺序都只产生一批通知，已完成任务不因其他项恢复而重跑。
- E 的工作区、资源、费用门禁未验收前，不只把 `max_workers=1` 改大上线。

## 7. G：以小样本证明收益

建议先准备固定的小规模任务集，覆盖文件编辑、命令自测、网页生成、接口实现、跨文件修改、权限解释、未知回执和并行集成。控制器故障样本用 mock；模型质量样本另行受控实跑，记录真实费用，不把等待阶段无主脑调用描述为全流程零额度。

每次保存输入、可见验收条件、制品、独立测试与版本；隐藏评测答案和 holdout 样本，但任务要求不能隐瞒。独立验收优先使用测试和实际文件检查，模型评分只作补充；完全访问模式下不能把“不放进提示词”称作评测文件不可读。

指标同时报告样本量、端到端通过率、可判定质量通过率、人工接手、整改、耗时、已知费用和未知费用占比。样本不足不生成能力排名；本地模型耗时与主脑/原生积分分开记录。禁止根据单个鹈鹕演示推定所有任务质量。

## 8. 首个建议开发包

先只做 A 阶段：收据保存异常 → 统一 unknown 返回 → 正式请求只读查询 → Codex/DSH 两入口离线契约检查 → 文档说明。

这一包不开放并发、不更换执行端、不改预算、不重试旧失败任务。通过后进入 B/C 的最小切片，再扩展诊断与并行。具体分支与提交在实际开发时建立，本次文档不等于已经开始实现。

## 9. 全程必须保持的约束

- 公共行为覆盖 Codex 与 DSH；WorkBuddy 执行端和 WorkBuddy 主脑角色分开验收。
- 不读取认证文件、密钥或无关聊天，不自动上传诊断材料。
- 不自动放宽权限、开启付费、调整模型/Agent、提高用户关闭的预算/调用限制或缩短无限任务运行时长。
- 结果未知、recovery_pending、取消任务不自动重发；整改上限继续有效。
- 执行器 completed 不是独立接受；主脑接手必须保留原始失败。
- 回归用临时项目、临时记录、mock provider；原生模型与 GUI 验收分开记录。

本计划为产品和工程建议。开始每项实现前需重新核对当时源码、适配器版本与宿主能力，不把 2026-10-23 的调研状态永久当作事实。
