## 问题与范围

首版在集成结果保存后才释放项目集成占用，能避免重复执行，但控制器恰好在两者之间退出时，完整成果与占用会同时留下。原 reconcile 只能标记待核对，无法完成这一步收尾。本批补这个有明确事实依据的缺口，不引入第二套调度器、超时解锁或自动重试。

四端执行器本身的未知结果、会话关闭与任务结算仍走原机制；本批恢复对象是**控制器的集成作业**，不能据此宣称四端中断恢复全部完成。

## 证据与操作

新领取将原租约快照（拥有者、进程、项目、领取时间）和完整进程身份绑定到原队列记录。只有原同步集成函数返回后，控制器才在同一次终态保存中写入 completion，绑定原领取、任务/冻结提交、合并与检查结果、输出提交和保留副本。后续独立验收与核对记录不改变这份执行证据。

这份内容摘要用于检测记录变化，不是抵御任意本机写入的安全签名，也不是全进程树或系统隔离证明。

| 当前事实 | 处理 |
|---|---|
| 完整新回执、计划对应的同步检查均有整数退出码、原进程确认退出、占用与原领取完全一致 | 明确核对后只释放这个作业的集成占用；原检查通过/失败、独立验收结论保持 |
| 本作业已不持有占用，另一作业可能已领取 | 只记录本作业已不持有；绝不释放另一作业 |
| 原进程仍在、身份不可读、租约变化或注册表不可读 | 保留占用并说明原因 |
| 仅合并提交已生成，但检查/完整终态未保存 | 保留现场及原占用，不从 Git HEAD 或答复推断成功 |
| 检查退出码缺失/超时、旧记录没有 completion | 不补造结束证明，不据此释放遗留占用 |

真正释放在原租约锁内重新比较**完整领取快照**，防止只比较任务名称造成竞争。核对写入与集成独立验收共用原记录锁，避免释放后紧接着的验收被旧核对结果覆盖。正常队列不增加额外收尾写入或扫描服务。

读取 `observe/snapshot` 只返回结构化 `recovery`：state、can_settle、中文原因；不写入记录、不创建锁文件、不运行 Git、检查或模型。页面显示“收尾与占用”，在完整结果待收尾时也提供核对入口；收尾与业务是否验收保持分开。

旧作业如果当前确实不持有占用，显示 `not_held`，不会因为缺少新证明就凭空产生卡住告警；这也不补认它的执行成功。`settled` 与 `not_held` 都不授权重新执行。

## 两主脑与共享页面

- Codex/DSH 共用正式 `brain_reconcile_integration(request_id, name)`；原项目、owner 和任务归属由受信连接决定。执行器角色与其他聊天不能接管。
- 核对使用自己的请求标识及原请求账本；重复已完成请求返回同一回执，不重复执行。响应未知按原请求查询，不重派。客户端核对操作、请求标识、集成名称和责任引用；损坏或错配回执保持 unknown。
- 核对返回 `integration.queue.reconciliation.state`；`settled` 表示本作业占用已核对，不表示集成检查通过或业务验收通过。普通面板不能处理绑定主脑的作业，会说明正式工具入口。
- 现有项目绑定 HTTP `/api/integrations/<name>/reconcile` 复用同一核心，普通控制器任务可明确确认核对；两种宿主页面共用组件。
- 核对不重新合并、不运行检查、不派发模型、不启动其他排队作业、不更新原树。之后需要继续尚未开始的原作业时，使用原有显式续接。

## 验证与保留边界

隔离临时 Git 项目、任务记录和租约覆盖：完整结果收尾、部分结果拒绝、活进程/未知身份、旧/变动回执、缺失检查退出码、失败结论保留、外来占用、同拥有者不同领取、重复核对、只读零写入，以及核对与独立验收竞争。

两个真实测试子进程分别在完整结果保存后/检查开始后主动退出。前者以真实 PID/创建时间证明确认退出并完成收尾；后者保留结果未知与原租约。只退出测试自有子进程，不操作真实桌面、服务、用户任务或账户。

两主脑通过真实 stdio→临时 HTTP→公共控制器验证正式核对、重放与原请求查询；共享界面验证包含窄屏/宽屏、深浅色、收尾确认后仍待验收。它们不等于原生桌面 GUI 或运行版升级验收。具体增量结果见本轮更新记录。

按用例去重累计 **192项 Python 通过、1项环境跳过**（目录符号链接权限不可用）；**66项 Node 用例、12项页面生命周期检查**通过，另有 **232条浏览器断言**覆盖两宿主、320/1100宽、深浅色。采用分组增量，不是全仓回归；开发中修正冗余正常收尾写入、更新新增工具的契约样例/计数及旧插件版本断言，随后仅复跑受影响检查，原失败不累计为通过。

Python 直接调用方覆盖队列、恢复、正式工具/HTTP、原集成与接受、租约、主脑上下文/请求账本/MCP、状态/归属和插件配置。可在配置好依赖的源码工作区复跑相应 `unittest discover`：`test_integration_recovery.py`、`test_integration_queue.py`、`test_integration_queue_gateway.py`，以及 `test_task_leases.py`、`test_task_integration.py`、`test_accepted_integration.py`、`test_integration_acceptance_gateway.py`、`test_brain_context.py`、`test_brain_requests.py`、`test_brain_mcp_server.py`、`test_task_status.py`、`test_brain_gateway.py`、`test_brain_ownership.py`、`test_dsh_brain_plugin.py`。
