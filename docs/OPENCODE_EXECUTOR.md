# OpenCode 原生执行端

本适配器通过用户本机 OpenCode **2.1.3** 的 `acp` 命令运行原生客户端。保留 `opencode/deepseek-v4.1-flash-free` 与 `opencode-go/deepseek-v4.1-flash` 的既有绑定，并可通过选择器读取当前原生目录中的 `opencode/` 和 `opencode-go/` 型号；分别绑定免费/Zen 服务与 Go 套餐；模型可用性、限免和账户限制由服务方决定。该版本两种原生集成都读取子进程的 `OPENCODE_API_KEY`，通过准确模型与 provider 策略区分服务，不改已有 DSH API 连接。原生独立目录探测已核实 Go 型号能由此变量加载；不能用其他 harness 的变量名代替。

ACP 握手只接受已审查的 2.1.3 / 2.1.4，CLI 就绪检查仍固定 2.1.3；其他版本不会被自动视为兼容。模型思考强度由原生元数据提供并在发送提示词前确认，目录存在不代表当前账户有权益或该型号通过真实任务验收。

## 连接和范围

可通过 `MODEL_DESK_OPENCODE_EXE` 或本机忽略文件 `.local-worker/opencode-runtime.json` 设置 CLI 绝对路径，也支持探测当前用户桌面版附带的 CLI。只读探测只执行 `--version`，不发提示词。原生二进制版本、SHA、ACP 父会话身份和选择后的 model/mode 随真实任务记录。

新安装执行端默认关闭。模型的默认 Agent 可设为 `opencode`；原有模型、旧任务和其他执行端保持原身份。公共工作台、Codex CLI/MCP 和 DSH 主脑调用公共控制器和相同队列。

任务绑定可信项目目录，并仅接受明确列出的文件。初始版本支持只读任务和限定文件编辑；**不开放终端、联网工具、子代理、会话续接或完全访问**。新任务和整改使用独立 ACP 会话。每个编辑任务在执行前备份列明的现有文件，不自动回滚并行工作。

## 原生策略与保护边界

每项任务使用独立 XDG 配置、数据、缓存和状态目录；不导入用户 OpenCode 账户数据库或全局配置。凭据只从已授权模型连接传入进程环境，不写入源码或业务提示词。运行配置包含专用 Agent，禁止所有工具和集成后，仅对列明文件开放 read/edit。启动后通过 ACP 设置并核实原生模型与专用 Agent。

ACP 文件回调再次检查实际解析路径、项目、父会话和读写类型；未知方法、终端与权限请求拒绝。`.model-desk`、运行配置和认证文件不能作为业务目标。原生策略负责客户端内部工具；这些控制**不是操作系统沙箱**，也不把未使用的 DSH 工具保护标成已生效。每项任务仍需主脑检查真实产物，执行器 completed 不等于验收。

## 预算与结果

原生 ACP 只提供聚合 token 用量，不能证明实际请求次数，也没有逐请求人民币预算拦截。因此金额或调用次数硬上限开启时明确拒绝，不自动关闭开关。保留云端授权、模型范围、执行端开关和任务的明确时限；不自动重发未知/失败结果，不以切换客户端规避服务限制。免费价格来自官方目录，不承诺长期免费或无限额度。

取消只通知/关闭本任务的 ACP 子进程及其私有服务，不终止用户的 OpenCode 桌面窗口或共享后台。结果、真实工具更新、文件 SHA、原生用量、取消和独立验收仍保存于所属项目的工作台记录中。

## 验证

`test_opencode_executor.py` 覆盖原生模型绑定、范围与记录目录拒绝、只读写入拒绝、Unicode、权限/未知方法/子代理拒绝、取消、预算开关、路由、项目及 MCP 入口。`test_ordered_native_routing.py` 另验 Go 身份与顺序。既有模型默认、执行端、主脑网关测试另做回归；`test_endpoint_cards.cjs` 分别以 Codex/DSH 宿主模拟视图检查六张执行端卡片。

离线检查不调用真实模型。真实任务通过工作台正式队列单独派发，验收结论另记，不将握手或模拟结果当作真实推理通过。
