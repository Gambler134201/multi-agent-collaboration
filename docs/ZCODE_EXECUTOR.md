# ZCode 执行端

## 原生连接与模式兼容（2026-10-25）

ZCode 3.16.3 的普通会话模式回执为 `build`；工作台只读任务显式请求并确认该模式，以只读原生工具白名单和 hook 同时限制写入/终端，不将 `build` 本身描述为操作系统只读沙箱。编辑任务保留 `yolo`。创建时的初始模式和随后显式切换的最终确认分别校验，未知/缺失模式、模型/会话不匹配以及最终模式漂移仍拒绝，不按意外回执静默回退。

卡片连接忽略已退出主程序留下的已知 Electron 辅助进程，并等待原生服务就绪后读取模型列表。真实主进程尚在运行且未开启桥接时，仍要求用户结束任务后退出；不强制关闭用户程序。任务收尾只关闭本任务专用会话和桥接客户端。

首版适配 ZCode Windows 3.16.3（自带 CLI 0.17.0）。使用桌面登录账户的明确原生渠道、模型和思考强度；不使用 API Key，不解密、读取或转存认证文件，不回退到其他模型。首个真实任务使用 Start Plan / GLM-5.3-Flash / max，写出两份 Python 文件、读回并运行测试，原生会话关闭后才发布终态。

## 使用

1. 在工作台的 ZCode 卡片打开“参数设置 → 模型与连接”，填写本机安装目录和本机桥接端口（默认 19765）。
2. 点击“打开 / 连接 ZCode”，连接成功后自动读取模型列表。可勾选“任务启动前自动打开并连接”；默认关闭，只在已授权任务启动前生效，预检和卡片轮询不会启动应用。如果原程序运行时没有桥接参数，等它的任务结束后完全退出，再通过此入口打开；不会杀掉或重启现有实例。之后可在 ZCode 正常工作，同时接收工作台的独立会话任务。
3. 读取原生模型列表，选择明确渠道、模型和思考强度，保存后启用卡片。思考档位来自该模型的原生目录，未手动选档时沿用已保存值或原生首选/已声明最高档。已有排队任务保留原模型与思考强度，桌面或卡片切换不改写旧任务。
4. 主脑通过模型 ID 派发或明确列入自动路由候选。保留既有手动默认模型，不因接入而迁移其他执行端。Start Plan 可手动刷新原生账户套餐额度，按模型、单位和到期时间分别显示；这不是本任务消耗或人民币余额。人民币费用/底层请求次数没有可靠逐请求计量，开启强制金额或次数上限时仍拒绝执行，不把未知显示成零。

## 运行、续接与额度

工具启动时就写入当前任务的进度，运行中可见命令、搜索、读图及文件操作状态；执行终态仍要等工具和原生会话关闭。指定自测命令需要真实哈希、退出码和工具证据；仅看到最终答复不算测试通过。

已正常结束且会话关闭确认的任务可“继续任务（新会话）”。控制器在同项目/同拥有者校验后，携带上一轮请求与答复的有界、脱敏交接，记录父任务与交接哈希，保留原模型、思考强度、权限和文件范围。新任务使用新的原生会话，既不是重发旧请求，也不是原生历史完整复用；实际原生会话复用仍不支持。结果未知、旧保护版本、跨项目、跨拥有者或扩大文件范围均拒绝。现有整改次数、阶段依赖和独立验收规则继续生效。

额度来自原生 `usageStatsService.getEntitlementSnapshot`，鉴权始终由 ZCode 宿主处理。适配器仅保留当前渠道的数字、单位、模型标签与到期时间，不接触 credentialService。刷新失败保留旧快照并报错，超过三分钟标记缓存过期；账户整体额度变化不能归因为单一任务。切换登录账户后应手动刷新。

## 桥接与工具边界

此版通过仅监听本机的 Electron 调试端口调用已安装版本的原生桌面服务；是版本绑定的适配器，不是 ZCode 稳定公共 API。匹配安装主窗口和渠道身份，不能连接任意调试页面。当前只支持唯一主窗口；升级 ZCode 后需要重新核验。调试端口属于本机用户的应用控制接口，不是对不受信本机进程的隔离层，不应转发到网络。

原生服务负责账户鉴权、模型调用、工具执行及会话生命周期；适配器只操作自己生成的随机会话，不枚举或读取其他聊天。新任务使用 ZCode 自带的 Read、Glob、Grep、WebFetch、WebSearch、Write、Edit、Bash，不加载工作台的 `modeldesk_zcode` MCP 工具。图片读取由原生 Read 支持；只读任务不开放 Write/Edit/Bash。无需修改安装包。子代理、动态工作流、后台任务及原生历史直接复用未开放；这不是 ZCode 主脑适配。

原生工具负责文件格式、编码、图片、搜索与命令结果。工作台不重复实现这些工具，也不把旧 MCP 的文件大小/网页解码限制描述为原生工具限制。目录 Grep 通过原生 PreToolUse.updatedInput 加入私有目录排除；它会替换该次 glob 过滤，模型可用更具体路径收窄范围。Glob 仅列出路径，不改写原生结果；明确指向受保护内容的读取/写入仍拒绝。联网使用原生 WebFetch/WebSearch，并保留本机/内网控制接口保护；未开放电脑控制、任意第三方扩展或发布工具。

隔离任务副本内的编辑任务获得声明式临时目录 `.modeldesk-task-tmp/`：测试脚本、运行产物与临时材料写在这里无须逐文件声明，目录内的字面清理也可用；原树、记录、认证与原生配置的既有保护检查先于该放行执行，只读任务、非隔离任务与旧任务一律不获得该目录。临时材料不算交付：不进 changed_files 与成果哈希，交付提交排除该目录；留有临时内容的副本回收前仍需人工确认。任务副本外的行为不变，这不是 OS 沙箱，动态脚本运行时计算的目标仍无法静态核实。

文件与命令通过原生 hook 调用已有公共记录/原生配置参数保护。项目范围限制显式路径和列明的业务文件；完全访问可以处理必要的项目外普通文件，记录、认证和原生配置仍受保护。真正策略拒绝会持续停止本任务；缺失文件、编辑冲突与合法命令非零退出由原生工具处理，不统一伪装成权限拒绝。

控制器向当前项目 `.zcode/config.json` 添加四个原生 process hook，只接管 `modeldesk-zcode-` 专用会话，普通 ZCode 会话旁路。只对本安装的四条 hook 声明请求原生信任，不代为信任其他用户 hook，不改全局登录设置。已有启用的 hook 和其他设置保留；项目若存在未启用的 hook 则拒绝自动启用，避免改变用户原意。hook 指向当前工作台安装与现有 Node；移动/卸载安装时需同步清理项目里的对应 hook。任务/会话/代码版本、配置哈希与事件由所属项目 `.model-desk` 记录；不在事件中保存原始参数或命令。

历史 `scoped-mcp-development-v1` 任务保留原配置，续接/整改不自动切换工具或扩大权限。新任务由控制器保存 `zcode-native-v1` 与原生 hook 指纹，不接受正文覆盖。旧 MCP 实现仅作历史兼容，不再作为新任务默认工具。

卡片的权限修改仅用于后续新任务，旧排队任务继续使用原权限快照；连接安装目录或端口改变则明确拒绝旧任务，不暗换宿主。任务前自动连接需同时满足当前开关和本任务创建时的授权，关闭当前开关可阻止后续自动打开；不会给旧任务追授自动启动权限。

生命周期恢复（P3）：任务连接后、发送提示词前，控制器把当前桌面主进程身份（pid、创建时间、命令摘要）钉扎进任务记录 `zcode_instance`；实例中途退出由桥接断开暴露为结果未知，自动重发仍被拒绝。对执行中死亡遗留的"会话关闭未确认"任务，`python zcode_worker.py --run-id <任务id> --finalize-session` 提供有身份证据的定向收尾：钉扎实例已退出或桌面未运行时直接确认关闭；实例仍存活时经原生服务只关闭本任务的 `modeldesk-zcode-` 会话（会话已不活跃也视为正面证据）。它从不发送提示词、不枚举或关闭其他会话、不停止桌面程序；无法核实实例身份或连接配置漂移时拒绝并保留资源。确认关闭后，既有的 `finalize_only` 控制器核对收尾即可只释放本任务资源并完成收尾；未确认仍被拒。

这不是 OS 沙箱，任意程序/脚本在运行时计算的目标无法完整静态验证。自动交付统计仅比较声明文件的哈希；不是全盘写入审计。自测通过不等于独立验收；指定命令需要匹配命令哈希、真实退出码和工具证据。回执未知、会话关闭未确认或保护版本变化不授权自动重发。

## 验证范围

临时记录与 mock 覆盖账户/API 互斥、范围/卡片/预算门禁、任务快照、工具保护、未知结果不重发，以及 Codex/DSH 主脑接口。浏览器测试覆盖两种宿主视图中的卡片和设置弹窗。真实账户验收限于下述小型任务，不代表全部内置工具、复杂工程、失败恢复、取消和所有模型均已通过。

体验对齐增加两轮真实任务：首轮搜索、读图、文件与终端闭环独立验收通过（8 个单测及类型边界）；第二轮通过独立新会话交接找回原标记，完成同文件续接（13 个单测、56 个合法组合、23 个非法类型独立通过）。两轮均固定 Start Plan / GLM-5.3-Flash / max，会话关闭后才验收，无重试。原生套餐权益已真实只读获取；网页工具、自动打开和启动前取消主要为隔离 mock/临时进程检查，未据此宣称所有真实异常场景或宿主都已验收。

两主脑共用控制器、执行器、费用未知语义和独立验收。旧的常驻主脑/MCP 进程需要重新连接以加载新增执行端；页面刷新不更新已载入的 Python 模块。没有更改 DSH 插件工具协议或冒充 DSH 原生新任务已实测。
