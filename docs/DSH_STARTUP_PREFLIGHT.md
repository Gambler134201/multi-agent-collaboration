# DSH 独立启动与新会话协作预检修复

日期：2026-10-20。候选插件：0.2.8。开发分支：`codex/dsh-startup-preflight`。

## 问题与判断

1. 原右侧入口只打开回环 URL，Host 插件和主脑 MCP 都不负责启动服务。Codex 的显式打开入口会启动后台，因此用户会观察到“Codex 打开过工作台，DSH 才能打开”。这属于入口启动能力缺失，不能依靠提示模型再开一次页面解决。
2. 原协作规则是长提示中的条件式流程，首次连接和任务归类仍由模型判断。另一本机时序事实是 DSH 0.2.1-rc.2 在 pre-step 前组装静态提示，随后刷新 runtime context；仅在 pre-step 注册/移除规则可能赶不上当前步骤。它能解释部分时序风险，但不能把每次跳过都断言为这一原因。

## 候选改动

- 显式点击 DSH 原生工作台入口时，通过宿主自己的受认证 Connection RPC 请求打开。Host 按原生会话 header 核对项目，然后启动/复用同一安装的工作台；前端在收到就绪确认后才导航，不要求 Codex 在运行。
- 新的 `panel_service.py` 只在明确 ensure 操作时执行原生 PowerShell 7 的 `打开模型工作台.ps1 -NoBrowser -Port ...`。导入插件、发现工具不启动服务；已有同目录服务复用，其他安装占用时拒绝，不停止、重启或替换任何进程。
- 启动脚本使用按安装目录区分的 Windows 命名互斥量，避免多个入口同时重复启动。服务仍使用独立 stdio，不继承聊天终端输出管道。
- 新增 `brain_preflight`：一次模型工具调用完成必要的显式连接、身份、总开关、范围及候选读取；生成结果带时间与原生工具记录，不调用执行模型、不派发、不改设置。后台缺少新状态字段时明确报不兼容，不推断开关。
- DSH 的受信启动参数允许该显式预检在服务缺失时按需启动；其他宿主默认没有这项启动许可。该许可不能通过模型工具参数更改。
- 每个顶层聊天注册独立的短 runtime context，包含真实开关、范围和项目，要求新会话首次响应先预检，后续新执行需求每轮一次。pre-step 在委托给后续处理前刷新状态，利用原生 runtime context 的后续刷新时序。
- 创作、文案、生成素材与文件都纳入派发评估。执行端能力合适、范围明确时优先派发；简单一步、核心风险决策、独立验收及执行端能力不足允许主脑处理，并说明理由。
- 开关关闭/不可读不注入自动派发提醒，不取消旧任务，不全局拦截普通宿主工具。原来的派发/整改权限守卫与后台门禁继续独立校验。

## 对建议的取舍

采用：可见状态、组合预检、靠近当前输入的激活提醒、明确首轮动作、创作类示例、派发/自做理由。

不采用“只要 write/bash 就无条件派发”：独立验收本身也需要读文件、跑命令，简单修改和风险决策不能被机械转交。没有预检的写入硬门禁与全量工作审计没有在本候选实现；因此不能保证任何模型都一定服从提醒。后续如真实无提醒测试仍跳过，应基于宿主执行证据设计门禁，不能把没有 task_id 的每一次主脑工作都标为违规。

预检工具结果是本轮可见留痕，不是全会话自动审计、密码学证据或派发完成证明。候选可用不代表适合本任务，仍由主脑评估质量和风险。

## 升级与任务保护

目前只在独立 worktree 开发，不部署到正在运行的 DSH/工作台，不复制运行密钥和任务记录，不发真实模型请求。

升级需要完整匹配后台、两份 PowerShell 启动脚本和插件八文件。新安装计划额外指纹覆盖启动 helper 与根目录启动脚本；旧安装收据必须保留，不能修改其指纹来冒充匹配。待执行任务结束后，再用原安装器/原收据卸载旧插件、部署匹配源码、重新准备并安装新候选；不把新安装器直接用于已经失配的旧计划。

替换已加载插件与 MCP 需要完全退出 DSH。后台重启只能在队列空闲且活跃等待已处理时进行；不能为了升级中断用户后台任务。安装器不替用户关闭或重启软件。

## 实机验收：需要分别通过

本轮离线验证：Python 完整回归运行 1118 项，1107 通过、11 项跳过；该轮临时指定已安装的 DSH 程序路径，只读加载厂商公开预设，不改用户环境。此前未配置该路径时两项环境依赖报错已核对；续接范围测试另补就绪 mock，避免依赖真实执行器。后补的环境继承过滤通过启动 helper 的 7 项定向检查，安装器 37 项通过；Node 主脑/侧栏/账户检查 58 项通过，两个 PowerShell 启动脚本解析通过。未发模型请求、未实际启动/重启后台、未装到真实 profile。

这些证据包含临时文件、mock HTTP/宿主、真实 stdio MCP 协议；不是新包的原生 UI 或真实模型轮次验证。原聊天通知的可选原生检查未启用，不把跳过算作通过。

1. **独立入口**：退出 Codex，工作台服务尚未启动时，独立打开 DSH 与原生工作台入口。应能在就绪后显示页面，项目正确。这个场景不能在 Codex 一直开着时声称通过。
2. **无提醒新聊天**：协作开关开启，在专用测试项目新建聊天，只提出普通创作需求，不提“协作”“派发”等词。检查第一个正式协作动作是否为 `brain_preflight`，能否读到真实 local_only/all 等状态，并产生明确的派发或有理由的自行处理决定。
3. **真实闭环**：选非单步任务，核对 task_id、真实模型/Agent、只订阅一次完成通知、独立验收。不能把工具发现或假宿主检查当作模型已自发遵守。
4. **关闭对照**：关闭协作，新建聊天后正常处理普通请求，不自动启动预检/派发；已有任务仍可取回和验收。
5. **异常对照**：服务不属于本安装、启动失败、切换/关闭标签页时，不打开错误项目，不停止其他服务，不自动重派。

示例无提醒需求（在测试项目中发送）：

> 创建一个可离线运行的星空动画 HTML，包含三种可切换效果、暂停/继续和速度调节，适配窗口大小，并附简短使用说明。请检查控制功能和页面错误。

测试提示不加入“必须先使用工作台”等提醒，否则不能检验自动进入流程。观察实际结果，不要求不适合的模型勉强接单。
