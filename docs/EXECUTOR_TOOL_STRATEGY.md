# 执行端工具策略

执行端使用各自原生工具；工作台负责路由、任务身份、必要权限校验、执行证据和独立验收。新增能力优先接原生接口，不重复实现文件、搜索或命令工具。

新任务的文件规则已在源码候选中改为[任务级契约](TASK_EXECUTION_POLICY.md)：交付清单不默认限制所有写入，明确文件限制和只读文件独立传递；四端接共同判断，旧任务不升级。常规命令错误由原生 Agent 纠正，必要保护拒绝仍保持。Shell 全文规则及整轮失败表达尚待后续收敛，不能概括成已经完全放开所有原生能力。

| 执行端 | 新任务的工具来源 | 工作台接线 |
|---|---|---|
| Pi | Pi 原生工具 | 任务会话与保护扩展 |
| DSH | DSH 原生工具 | 预设、参数保护与事件流 |
| WorkBuddy | 原生开发工具 | 原生配置与 hook |
| ZCode | 原生 Read/Glob/Grep/WebFetch/WebSearch/Write/Edit/Bash | 原生会话、项目 hook 与证据 |

历史 WorkBuddy 限定文件 MCP 模式、ZCode 自建 MCP 模式只保留旧记录/任务兼容，不静默把旧任务升级为原生工具。子代理、后台任务、发布和其他高影响能力仍按各自授权与能力边界处理；原生工具不代表任意权限。

2026-10-24 源码审计发现：WorkBuddy 旧限定文件模式会把编辑冲突等普通错误暂停为整轮写入失败；新原生模式不走此路径。Pi/DSH 的输出已用替换解码，不存在 ZCode 旧适配器相同的解码崩溃；其控制器测试输出仍可能出现中文乱码，未在中文 Windows 环境实测。Pi 对非法 JSONL 控制数据停止属于协议完整性保护，本次不放宽。WorkBuddy hook 内部异常拒绝时的证据可观测性仍可改进，不能据此认定调用被放行。

上述审计与本次原生接入的模拟/临时进程检查不是全部执行端的真实模型验收。具体原生验证范围记录在各执行端文档；没有测试的路径保留未验证。
