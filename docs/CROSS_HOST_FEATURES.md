# 跨主脑功能更新约定

## 可编辑的模型顺序栏（2026-10-25）

每个顺位新增“选择客户端 / 模型”，复用公共可搜索选择器，先选 DSH、Pi、WorkBuddy、ZCode、OpenCode 或 CommandCode，再选择其 API/原生目录模型与已声明思考强度。顺位始终显示所用客户端、型号和强度。确认只产生内存草稿，不改执行端当前模型；取消或重置不保存。最终保存统一校验各选择及来源版本，注册独立模型变体并写入顺序，失败时回滚两份配置。每个选择独立绑定来源和型号，继续浏览其他型号不会使未变的草稿失效；客户端连接改变需重新选择。保留原保存接口与已保存模型的快捷选择。

执行端上方的顺序摘要改为公共排序栏，每个顺位下拉选择已保存模型，可上移、下移、添加、删除或保留空位。选择已占位模型会交换两个顺位；默认保留原顺序，所有修改先进入草稿，显式保存后仅影响后续自动任务。关闭指定顺序沿用原自动路由规则，不改变协作开关、执行端、Key、预算或权限。

Codex、DSH、普通浏览器共用 `routing-priority-view.js`、`routing-priority-controller.js` 和原 `routing_priority.py` 保存接口。明确缺失/停用的模型和原空位不被自动替换，界面如实说明；后台仍执行能力、范围和授权检查。轮询保留编辑草稿，其他窗口或模型选择器改变顺序时提示冲突；新排序栏保存携带原始快照，在锁内校验后再写入，避免覆盖别处的新设置。保存失败保留草稿，不自动重试。

离线检查覆盖纯渲染转义、顺位交换与编辑、保存/重置、轮询与并发冲突、失败保留和窄屏布局；实际安装页面只读核对另行记录，不自动修改用户的当前顺序。原生主脑入口可见性仍由人工确认。

## 可搜索的模型与思考强度选择器（2026-10-25）

卡片当前模型按钮打开公共选择器：按来源分组、本地搜索、管理已有 API 连接、读取 API `/models` 和 WorkBuddy/ZCode/OpenCode/CommandCode 原生目录。API Key 由既有本机注册表内部复用，页面仅见已配置状态；管理连接留空保持密钥，可显式替换。通用 API 未声明思考协议时仅提供默认，原生强度按客户端实际选项显示并在执行前确认；目录和额度不代表型号能力已通过任务验收。OpenCode CLI 2.1.3 对应的 ACP 实测版本为 2.1.4，两者只接受明确版本及既有模型/模式和文件保护检查。

打开、搜索、取消、读取目录不派发任务；服务拒绝目录查询时显示真实错误，已保存模型可重新选择。确认应用创建独立配置变体，保留原模型 ID 和排队/运行任务；默认勾选更新该执行端在自动顺序中的候选，其余执行端与明确空位保持原顺序，取消勾选保留自动顺序。不会启用执行端、放宽权限或更改预算上限。跨文件保存失败回滚，来源变化与过期目录要求刷新。

浏览器、Codex、DSH 使用相同 renderer/controller 和既有 endpoint_settings 信封。两主脑离线 DOM 检查覆盖搜索、强度、保存、取消、Key 管理和窄屏；真实原生目录及强度元数据另行读取，不因此声称所有型号已完成真实生成测试或 DSH 原生入口已人工验收。

## 原生账户额度与同步设置（2026-10-25）

WorkBuddy、ZCode、OpenCode Go、CommandCode 的卡片额度与同步设置共用 `native_quota.py`、`native-quota.js` 和 `quota-controller.js`，Codex MCP Apps 与 DSH 工作台使用相同资源和既有 `endpoint_settings` 保存信封。渲染和状态读取只读取本机快照；显式刷新或已开启的可见页面自动同步才请求账户接口，不派发任务或调用模型。设置独立保存，不改执行模型、权限、预算、额度强制上限或任务记录。

OpenCode Go 固定调用官方 `/inference/go/v1/usage`，使用所选已有 Go 账户连接，免费模型没有独立额度接口。CommandCode 1.86.1 使用哈希固定的原生账户查询实现，移除 CLI 启动入口，仅调用与 `/usage` 相同的账户方法，客户端更新后拒绝查询并等待重新适配。WorkBuddy 5.8.3 与 ZCode 3.16.3 通过本机桥接调用原生账户服务，认证保留在客户端。既有实例缺少桥接时提示用户保存工作后重开，不自动关闭客户端。

剩余量、百分比、重置时间、来源、上次成功与最近尝试分别保留。缺失总量不画满额进度，查询失败不改成零，不同账户/单位不混加。来源变化不显示旧账户快照。离线单测、两主脑模拟浏览器检查与真实账户查询分开记录；原生桥接未连接保持明确的失败状态，不据此宣称完成同步。

## OpenCode 原生执行端（2026-10-24）

Codex CLI/MCP、工作台和 DSH 主脑共用 OpenCode 的执行端设置、模型默认 Agent、队列、项目绑定、预算授权检查、结果与独立验收记录。适配 OpenCode 2.1.3 ACP，仅开放指定免费模型和明确文件范围；不开放终端、子代理或旧会话续接。两宿主模拟页面验证不代表 DSH 原生入口已人工验收；真实队列任务另行记录。详见 [OPENCODE_EXECUTOR.md](OPENCODE_EXECUTOR.md)。

## ZCode 执行端

Codex/DSH 的主脑路由、派发、状态、交付、独立验收和共享工作台均已接入 `zcode` 执行端；每卡独立开关与统一预设沿用公共实现。两主脑接口使用隔离记录验证；真实 Start Plan / GLM-5.3-Flash / max 文件/终端任务另行记录，不据此声明 DSH 原生发起任务已验收。ZCode 为执行端，不是新增主脑。既有常驻 MCP 连接须重新加载新模块；使用方法及原生工具边界见 [ZCode 执行端](ZCODE_EXECUTOR.md)。

ZCode 的任务前自动连接、模型/思考强度保存、原生套餐权益刷新、运行中工具进度与带交接的新会话续接同样位于共享执行端及控制器；两宿主使用同一张卡片和保存信封。旧任务保持模型/权限快照，旧保护版本不自动迁移；卡片预检不启动应用，自动连接不重启正在工作的 ZCode。套餐余额不能代替逐任务成本，强制计量上限仍按原规则拒绝。原生内置工具未全量放开，文件/搜索/读图/网页/终端由受控 MCP 实现。两宿主离线覆盖与真实原生验证分开记录。

## 执行结果与失败阶段

## 项目地图

交互架构图在共享地图 JS/CSS 中实现，Codex MCP Apps 内联同一份资源，DSH 浏览器入口由同一后台提供；入口和主脑插件无新增协议。讲解图、通用项目静态模块图及代码细节遵循相同证据边界。离线多宽度浏览器检查与原生嵌入页确认分开记录；已打开的旧页面需要刷新或关闭重开以载入新资源。

## 请求回执可靠性与原请求查询

## 收尾清理与保护诊断

共享 `record-policy.cjs` 的命令组判定同时覆盖 DSH、Pi 和 WorkBuddy，区分具体临时文件清理、独立只读列表和实际破坏性管道。WorkBuddy 的原生钩子额外拒绝未核实变量/通配符递归清理，并记录脱敏固定规则标识；Codex/DSH 主脑读取同一执行端任务错误和工具明细。旧拒绝不自动重跑或改状态。离线策略、模拟原生钩子与已安装执行器连接本地模拟接口的测试，不等于真实模型复验。

## 执行端访问权限

Codex/DSH 共用 Pi、DSH、WorkBuddy 卡片内“参数设置 → 模型与连接 → 访问权限”。选择后立即保存，按执行端应用于其全部模型；Pi/DSH 未保存时保留既有完全访问。新任务由控制器记录权限快照，正文参数不能覆盖；排队、运行、恢复、续接与整改保持原任务权限，历史 Pi/DSH 无快照任务按原完全访问处理。只读聊天不获得写入或终端权限。

DSH 项目范围使用原生 `workspace-write` 策略并追加工具参数校验，完全访问使用 `danger-full-access`；Pi 项目范围只有工具参数校验，没有操作系统沙箱。两者的显式路径检查处理真实路径/目录联接及常见终端字面路径，无法推断任意脚本动态计算的路径；工作台记录保护始终生效。文件统计仍只覆盖声明文件，不是全盘审计。更新保护代码后旧原生会话可能因指纹变化拒绝续接，应创建新任务，不隐式换会话。

本次验证包括保存与任务快照的离线控制器测试、Codex/DSH 浏览器模拟视图、已安装 Pi/DSH 执行器连接本地模拟提供方的工具测试；不代表消耗真实模型额度的任务验收或两宿主桌面 GUI 人工验收。

通用能力更新必须覆盖全部已支持的主脑；当前为 Codex、DSH。WorkBuddy 尚在适配中，不算已完成支持。这里的全局是当前安装及其本机项目，不意味着其他电脑或尚未适配的 Agent 自动获得能力。

## 更新步骤

1. 先判断通用核心还是宿主专属功能。范围、路由、验收、记录、状态语义等优先复用公共实现；原生入口、账户来源、消息唤醒由适配器接入。
2. 列出 Codex、DSH 的触发入口、共享实现和生效方式。新宿主沿用同一行为契约，缺少原生能力要明确显示未支持，不伪造等价能力。
3. 为公共行为及每个入口运行必要检查，覆盖项目未知、开关关闭、无可用候选、异常和正常路径。只读预检不得调用模型、派发任务、创建项目记录或为了提示启动服务。
4. 更新全局规则模板和安装器覆盖的入口；保留用户规则、设置、历史及已在运行的任务。已有聊天的旧指令和常驻进程不承诺热更新。
5. 分别记录源码检查、部署检查、真实宿主验证。仍有适配器缺失或未验证时如实列出，不能以一个宿主通过概括全局通过。

## 原生 PowerShell 7 依赖

Codex MCP、DSH/通用主脑的公共启动器、系统目录选择器共用 `powershell_runtime.find_pwsh`。调用宿主的 PATH 不应决定相同机器上是否能启动。现有 PowerShell 7 可来自系统安装、显式绝对路径或本机缓存；不要求 Codex 运行，但仍依赖该可执行文件实际存在。没有原生 PowerShell 时明确拒绝，不自动下载、不换 shell。

独立启动验收必须区分“已有后台时复用”和“无后台时冷启动”。只检查复用不能证明独立启动。`probe_panel_cold_start.py` 在临时安装中运行真实启动脚本，以不含 Codex 环境/PATH 的环境启动 fixture HTTP 服务并复用，模型/记录/真实端口均不参与；实际桌面验收另记。

## 执行端设置弹窗与统一预设

Codex/DSH 共享紧凑卡片、设置弹窗首页及四项执行端预设；模型连接在第二页签。`execution_endpoints.apply_preset` 按最终执行 Agent 合成有效能力，路由与主脑候选共同使用；旧任务保留快照。未保存时沿用各模型原预设，不自动迁移。实际模型价格、账户与预算不合并。WorkBuddy 作为执行端使用同一预设，作为主脑仍未适配。本次为离线控制器及两宿主浏览器视图检查，不等同原生推理验收。

公共终端保护已修正前置目录切换误拦、`cwd/workdir` 解析、条件分支及链接目录处理；Pi/DSH 项目范围同步检查相对 `cd`，WorkBuddy 继续验证原生配置与会话边界。两主脑共用同一执行端策略；没有放宽完全访问设置之外的保护，也不改旧任务快照。详见 [终端保护与验证边界](SHELL_GUARD.md)。

WorkBuddy 原生工具初始化与公共派发入口统一接受项目内的绝对/相对文件路径，仍解析实际路径拒绝项目外目标和别名。该修正位于共享执行器，Codex/DSH 都适用；两宿主在全新临时项目中的编辑与只读绝对路径请求有隔离回归，真实用户项目复验另记，不自动重派旧任务。

WorkBuddy 访问权限属于共享执行端设置：Codex/DSH 使用同一“项目范围/完全访问”选择，默认项目范围，新任务保存权限快照。完全访问要求原生双重确认 `fullAccess`，不以桌面聊天当前开关或仅 CLI 参数作为证明；仍保留记录与认证数据的参数保护，原生 GUI 发起的完整任务验收另记。

## OpenCode / CommandCode 和有序模型候选

Codex CLI/MCP、DSH 主脑 broker 和页面共用原生执行端、模型默认 Agent 与顺序策略。OpenCode 的免费与 Go 型号独立保存；CommandCode 无对应免费 DeepSeek 时保留显式空位。顺序只选择新任务候选，不续接或重发旧任务。页面同时显示顺序、缺位和未知账单；硬上限不能由原生执行端绕过。两宿主页面模拟与 Codex 发起的真实队列任务是不同证据，未据此声称 DSH 原生聊天实际派发已通过。见 [OpenCode](OPENCODE_EXECUTOR.md) 与 [CommandCode](COMMANDCODE_EXECUTOR.md)。
