# WorkBuddy 原生执行端

状态：2026-10-22，正式队列、路由、取消与主脑交付读取已接入公共控制器，并通过隔离测试；**Codex CLI → WorkBuddy 5.8.3 的真实单文件任务已分别在 DeepSeek V4.1 Flash、GLM-5.3-Flash 上独立验收通过**。DSH 原生入口派发 WorkBuddy、完成通知、取消与恢复的真实验证仍未完成。WorkBuddy 主脑适配仍是独立任务。

## 正式队列接入

- Codex 与 DSH 通过公共路由和 `workbuddy_worker.py` 派发；WorkBuddy 卡片可读取原生内置模型列表并保存选择，原有 Pi/DSH 模型及手动默认选择不变。API 模型不能借 WorkBuddy 调用，原生模型不能落到其他执行端。
- 列表读取只创建并关闭本工具自己的无提示词元数据会话，不读取其他聊天或认证文件，不发 `session/prompt`。缓存绑定安装版本/公开文件指纹及配置目录；环境变化后要求刷新。仅列出明确模型，排除 Auto、快速/均衡/极致等路由模式。界面不把限免、折扣写死，实际账户权限仍由原生任务核实。
- 保存选择会为该模型保留独立且不可换绑的注册标识，并更新 WorkBuddy 端当前选择；其他模型、手动默认值、开关、预算不变。旧模型行不被覆盖，排队/运行/整改任务仍按记录的原模型执行。新会话在发送提示词前仍要求原生确认指定模型，失败不替换。可读取/选择不等于已实测；目前真实单文件闭环证据覆盖 DeepSeek V4.1 Flash、GLM-5.3-Flash。
- 在 WorkBuddy 卡片内保存安装目录和当前用户配置目录；只校验公开安装身份，不读取认证文件。连接保存在忽略的 `.local-worker/workbuddy.json`，也支持显式 `MODEL_DESK_WORKBUDDY_HOME` / `MODEL_DESK_WORKBUDDY_PROFILE`。保存不调用模型，初始禁用不会自动开启。
- 需要已打开、已登录且同配置目录的 WorkBuddy；当前仅允许 5.8.2、5.8.3。5.8.3 的公开原生会话/ACP/受控工具接口已复核并通过离线回归，真实任务验收另记。其他版本仍拒绝，不自动放宽。安装/宿主就绪不等于实际授权已经验证。不自动启动 GUI、不复用既有聊天、不读取其他聊天。
- 新任务支持原生项目检索、文件编辑、终端自测和联网读取；旧任务保持原限定文件配置。每个任务/整改新建原生会话，嵌套代理与旧会话续接未开放。工具保护并非 OS 沙箱，主脑仍独立验收。详见末尾“原生开发工具配置”。
- 卡片开关、模型范围、付费授权都适用。原生积分未同步、调用次数未知、人民币费用未知，均不记零；因为无法执行工作台金额/请求硬上限，启用这些上限时拒绝原生调用，不能暗中关闭上限。
- 手动派发可明确选择原生模型；自动路由还需主脑把它纳入 `eligible_model_ids`，未知费用不作为最便宜模型。低风险文本/文件能力声明不是复杂任务能力证明。
- 取消只标记本任务并由 worker 关闭它自己创建的原生会话，不终止 WorkBuddy GUI。关闭失败保留未知状态；已发送、响应未知或清理未核实的请求不得自动重发。只有确认提示词尚未发送且原生会话已关闭/未创建，才能显式恢复。
- 原生使用量保持未知；正式状态/交付返回执行端、原生会话、清理和提示词尝试标记。`completed` 不等于验收通过；沿用项目记录、独立验收与完成通知机制。

- 由现有 Codex / DSH 主脑派发任务，WorkBuddy 作为执行端。
- 优先使用 WorkBuddy 登录账户自带的模型与积分。

## 已实现和验证

实现位于 `.local-worker/workbuddy_executor.py`：

1. 只读识别本机 WorkBuddy 5.8.2 安装身份，计算自带 CLI / 产品文件哈希。导入与 `availability` 不启动程序、服务或模型。
2. 使用安装包自带 `cli/bin/codebuddy` 和 `codebuddy-lite-wb.mjs`，由 WorkBuddy 自身的 Electron Node 运行，不安装另一个 CodeBuddy。
3. 此版本单独 `--acp` 会在本机静默退出；已验证 `--serve --acp` 返回真实 ACP 1 握手和新会话响应。保持原生 HTTP 鉴权默认值，不使用 `--auth none`。
4. 配置目录来自显式参数。桌面产品目录交接由原生客户端读取其 `cache/acc-product-config-v3.json`；适配代码不打开此缓存内容或认证文件，不复制令牌。隔离预检使用临时 HOME，不引用桌面目录。
5. 已在原生响应核对 `deepseek-v4.1-flash`：模型目录、`models.currentModelId` 和 `configOptions.model.currentValue` 一致。模型选择还需在发送提示词前再次获得原生确认。
6. 只接受 `session/prompt` 的权威结束标志；截断、拒绝或断线不算完成。已发送而无结果时标未知，不重发。
7. 默认禁用全部内置工具和外部 MCP：`--tools ''`、空且严格 MCP 配置、禁用会话落盘和项目/用户设置来源。显式提供任务工具配置时，只通过 ACP `session/new` 挂载下述受控文件 MCP。不支持终端、会话续接或嵌套代理。
8. 原生人民币费用、积分扣减未知时保留 `null`，不记为免费。强制金额或请求上限开启时拒绝原生调用，不关闭用户上限。
9. 底层安装探测本身不报告可派发；正式 `workbuddy_worker.availability` 结合明确配置、已验证安装和同账户宿主通道报告就绪。实际登录授权仍由原生任务核实；原有本地/Pi、DeepSeek/DSH 路由不变。

这些底层机制已用真实 Python 子进程模拟 ACP 做离线回归；不调用真实模型作为回归。

### 受控文件工具候选：隔离检查与原生挂载通过

新增 `.local-worker/workbuddy_tools.py`，通过现有 MCP SDK 的 stdio 连接提供三个工具：`read_file`、`write_file`、`edit_file`。没有终端、网络、账户、设置修改或子代理工具；WorkBuddy 内置工具保持禁用。

- 配置必须属于明确项目的 `.model-desk/runs/<task_id>`，绑定文件白名单、一次性任务 nonce 与当前保护代码哈希；同一执行配置不能被静默覆盖。
- 文件操作只接受白名单内的相对路径，拒绝 `.model-desk`、`.git`、项目外路径、路径穿越、Windows 设备/流路径，以及受保护目录别名和硬链接；读写限制为 2 MiB UTF-8 文本。不存在的可读目标返回 `exists=false`，允许模型随后创建新文件。
