# 执行端卡片与独立开关

## 访问权限

每张执行端卡片的“参数设置 → 模型与连接”首项可选择“项目范围 / 完全访问”，选择后立即保存。设置覆盖此执行端的全部模型，仅用于新任务；旧任务、整改、续接与恢复沿用原权限。Pi/DSH 保留原默认完全访问，WorkBuddy / ZCode 新安装默认项目范围。

Pi/DSH 配置在本机忽略文件 `endpoint-access.json`，WorkBuddy 沿用独立的 `workbuddy-access.json`。权限设置不修改开关、模型、预算或认证信息。DSH 项目范围使用原生 workspace-write 与参数校验；Pi 仅有工具参数校验，不提供操作系统隔离。任意脚本动态路径不是静态校验能保证的边界。工作台记录保护和只读任务限制始终保留。保护代码升级导致旧会话指纹失配时明确要求新任务，不自动升级会话。

2026-10-21。模型工作台从模型卡片改为 Pi、DeepSeek Harness、WorkBuddy 执行端卡片。模型连接、密钥、思考等级和 Agent 参数归入对应卡片；卡片保持紧凑，参数设置使用弹窗。余额始终注明账户来源，未知不显示为零。

## 行为与兼容

- 开关是本机工作台全局配置，由 `.local-worker/execution-endpoints.json` 独立保存；不改模型密钥、默认 Agent、预算、付费授权或旧任务。
- 未有配置时保留 DSH/Pi 原行为；新 WorkBuddy / ZCode 卡片初始禁用。只读状态不创建该配置；配置损坏时拒绝新派发，不自动重建或放宽权限。
- 禁用阻止新任务；排队任务、显式恢复和直接启动的执行 worker 在启动前检查。运行中任务继续，不能把禁用等同于取消。
- 自动路由按每个最终候选的实际执行端检查。显式任务覆盖只能使用已启用的目标端；旧 direct/Aider 入口也不能借此绕过模型归属端的禁用。
- 卡片内的“自动路由使用模型”是可选限制：未选择时保留原有多个模型候选；选择后只限制该端自动路由。手动任务仍可明确选此端其他模型，已有任务、整改和会话不迁移。已选模型被删除或改属时明确提示，不自动换成其他模型。
- 旧 `model_scope` 留在“预算与权限 → 兼容设置”，与卡片开关叠加。已有仅本地/仅付费范围不自动改为全部，卡片启用不意味着付费授权。
- 旧版后台没有执行端载荷时保留旧模型卡片及编辑入口，避免前后端升级短暂不同步时丢失管理能力。

## 宿主覆盖

| 入口 | 共享行为 |
|---|---|
| Codex CLI/工作台/MCP Apps | `model_router.choose`、启动检查、`execution_endpoints.gate`；MCP 只增加固定执行端设置接口白名单 |
| DSH 主脑与侧栏 | 同一控制器路由、候选与启动检查；候选及通用首轮状态信号排除禁用端 |

界面通过已有 `/api/workflow` 白名单通道发送独立 `endpoint_settings` 信封，兼容尚未重建的 Codex MCP 代理。控制器拒绝将它与范围、预算或授权字段混合保存；固定 `/api/execution-endpoints/{pi,dsh,workbuddy,zcode}` 接口供新客户端使用。

页面通过模拟接口分别以 Codex/DSH 宿主参数运行，不冒充原生宿主人工验收。此次不改 DSH 插件包；宿主入口、登录账户、自动唤醒仍由既有适配器处理。

## 执行端统一预设与设置弹窗（2026-10-22）

点击卡片“参数设置”打开弹窗，首页直接设置任务类型、能力说明、成本定位和自动派发复杂度上限；“模型与连接”页签管理模型、原生模型选择及运行参数。打开、关闭设置不会改变卡片高度，也不调用推理。

四项预设存放在执行端的 `preset` 中，应用于该端全部现有及未来模型，包括 WorkBuddy 后续切换的内置模型。路由按实际解析出的执行端应用预设，主脑候选也返回相同有效值及 `routing_preset` 来源；新任务的路由快照保留当时的值。保存不会改写模型连接或原始模型配置，也不迁移旧任务。API 实际单价、模型上下文、思考与运行参数仍分别保存。

兼容旧配置：首次打开不自动选一个模型的预设推广到整个端。未保存统一预设时沿用各模型旧值，首页明确提示；用户保存后才覆盖该端四项有效值。能力声明不代表实测能力；成本偏好不改变预算、付费授权或实际计价。

Codex 与 DSH 共用弹窗、保存信封、候选与路由实现。本次检查使用临时配置及 mock provider；两宿主浏览器视图分别验证，不能据此宣称原生模型质量或全部内置模型已实测。

本次统一预设相关离线回归 415 项通过；Codex/DSH 两视图的真实浏览器 mock 检查通过，覆盖弹窗、模型编辑、运行参数、草稿、独立保存、原生模型选择与窄屏。测试中修正了 Python ACP 模拟进程在 Windows 中文工作区的 UTF-8 管道编码，使模拟协议与实际 Node 宿主一致；未改原生执行逻辑。
