## 用户看到什么

选择明确项目后，点击项目栏的“任务关系”。按目标选择计划，从上往下看已有阶段依赖，点击方框查看中文说明、前置阶段、等待原因、执行端和实际模型、关联执行任务、验收条件及成果交接。前置阶段名称可以点击跳转；交付任务按钮返回现有任务详情。

每个方框代表计划阶段，不是自动生成的新任务。一个阶段可以有多次执行或整改记录。图只使用 `depends_on`，不根据标题、时间或 ordinal 猜测连线，不虚构集成、验收或交付节点。没有阶段的目标显示空状态；未关联阶段的普通任务单独列出，不计入目标进度。历史目标明确标注已完成或已取消。

同层排布不证明实时并发，也不代表自动授权；实际依赖、费用和资源门禁仍由原有控制器维护。没有正在执行的记录时不伪造执行模型；固定模型仅标为计划。只读分析阶段的文件列为上下文，不当作变更承诺。

## 数据与权限边界

- 复用已有 `/api/tree`、`/api/state` 的项目快照；图本身不发送请求、不启动模型或额外轮询，不调用阶段同步、派发、取消、恢复、集成或写接口。页面原有项目定位记忆行为不变。
- 原结构化 `stage.summary` 是状态来源；旧记录回退只读结构化阶段状态，不解析 phase、回答文本或错误关键词。执行结束不等于独立验收。
- 成果区区分预期文件和实际交接，保留交接有效、过期、未知和读取异常；查看不是重新验证或接受交付。
- 必须选择单个明确项目；前端对目标和任务再次核对项目归属，未知/全部项目不展示图。项目切换关闭弹窗并清除选择；API 的原有 epoch 校验防止旧响应回填。
- 树读取失败显示错误；已有内容标为最近快照，不伪装实时。缺失前置、重复标识、环路及受环路影响的阶段明确警告，不推断依赖已满足。
- 本组件最多绘制 80 个阶段，当前后台单目标响应上限为 50；真实 stage_count 大于返回数时明确提示不完整。后台目标/任务返回上限沿用原有机制，首版不增加分页或完整性承诺。
- worktree、调度、权限、预算、任务原始记录、验收与未知结果规则均未变动。
