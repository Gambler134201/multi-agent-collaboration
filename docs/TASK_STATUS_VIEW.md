本轮在 `codex/task-status-20261027` 源码候选开发，日常运行版保持 0.2.15；不部署未验收代码。原有调度、验收、取消、权限与未知结果规则不变，不引入第二套状态机或账本。

## 主脑拥有的核心

- `execution_result.project` 保持纯投影，新加 summary 与文件变化归属说明。
- `task_status` 根据结构化执行、验收、收尾及集成事实生成中文摘要，不从 phase/error 关键词判断状态。
- `integration_status` 只在受信项目绑定/真实项目记录路径下读取有界集成元数据；不初始化项目、不跟随记录链接、不执行 Git/模型或写记录。页面批量读取共用一次请求内快照，不保存长期缓存。
- Codex CLI、DSH/通用正式接口、工作台和阶段视图接入同一核心。缺少证据明确待核对，多个不同集成结论不能任意选一条。
- 没有集成记录不能显示“正在等待集成”；目前可确证的是“集成检查通过，等待主脑独立验收集成”。真实排队要等持久化集成队列实现。

## 展示组件契约（非核心，可由执行端实现）

仅新增 `panel/task-status.js`、`panel/task-status.css` 与 `tests/test_task_status_component.cjs`。禁止修改核心模块、app.js、index.html、配置或真实记录；页面接线与验收由主脑负责。

JS 无依赖、无网络、无 DOM 写入或事件副作用，只输出已转义的 HTML；暴露 `globalThis.ModelDeskTaskStatus` 和必要时的 `window.ModelDeskTaskStatus`，可同时提供 CommonJS 导出。API：

- `valid(summary)`：schema 必须严格为数字 1，source 必须为 controller_projection，code 是短 ASCII 标识，label 是非空字符串。
- `render(summary)`：不合法返回空字符串；合法返回紧凑的中文状态区块，展示 label、detail、next_step（“下一步”）和最多 4 条 facts。固定 aria-label=任务当前进度，data-status-code 使用经过验证的 code。
- `badge(summary)`：同样验证，返回小尺寸状态标签，供列表/阶段标题使用；不能根据任何其他原始字段自行决定状态。

输入示例：

```json
{"schema":1,"source":"controller_projection","code":"awaiting_review","label":"等待独立验收","tone":"warning","detail":"执行器已结束，但主脑尚未确认成果符合要求。","next_step":"主脑检查实际文件和测试后记录验收。","raw_status":"completed","facts":[{"label":"执行","value":"执行结束"},{"label":"验收","value":"尚未独立验收"},{"label":"收尾","value":"已确认"},{"label":"集成","value":"未记录集成"}]}
```

tone 仅允许 neutral/accent/success/warning/danger，其他值降为 neutral。所有文本转义，不能把传入文本作为 HTML、class、URL 或代码执行；未知/坏类型应保守降级。限制显示长度，防止巨大字段撑坏页面，但不得用省略伪装验收通过。

样式融入现有深色/浅色工作台，使用独立 md-task-status/md-task-badge 类名前缀；紧凑细边框、可折行事实行，无大面积亮色或巨型卡片。约 320px 宽度可用，长文本/中文不产生横向溢出。没有操作按钮、自动调用或新增权限。

## 验收范围

1. 状态优先级、原始事实保留、历史数据降级、只读文件变化归属有独立测试。
2. 项目绑定/集成输入匹配、过期/冲突/多记录/损坏记录和不初始化空项目有正反例。
3. 两主脑、CLI、列表/详情/阶段状态一致；新静态资源同时接入独立网页及 Codex 内联页面，不能重现“资源未加载”。
4. 展示组件离线安全测试、两宿主 mock 页面及窄宽度浏览器检查通过；不得据此声称原生 GUI 已验证。
5. 默认增量回归，保护用户已有文档修改和运行安装；真正部署与主脑连接重载另记。

## 仍保留的边界

- 没有持久化集成队列，因此不能把“未记录集成”画成“等待集成”。
- 权限、调度、通知、恢复、Git 集成和用户设置均不因状态展示获得新能力。
- 摘要是对现有记录的只读解释，不能代替真实文件/测试检查，也不是防篡改证明。
- 新资源与共享 Python 模块需要成组部署；仅刷新页面不能使旧常驻主脑进程加载新代码。
