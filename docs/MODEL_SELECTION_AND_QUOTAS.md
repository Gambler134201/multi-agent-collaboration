# 模型选择、优先级与额度同步

面向工作台的日常使用说明，覆盖执行器卡片、优先级顺位的客户端/模型编排，以及原生额度卡。内容仅基于当前已实现的行为；未声明支持的场景请一律视为未验证。

## 一、本次新增了什么

- **六张执行器卡片**：Pi、DSH、WorkBuddy、ZCode、OpenCode、CommandCode。Codex 与 DSH 共用同一套界面与控制器；两者的原生宿主菜单是否可见仍需人工确认。
- **卡片模型选择器**：点击卡片"当前模型"区域打开可搜索列表，支持按模型名称、模型 id、来源搜索，并可按来源过滤。候选来自 API `/models` 元数据以及已安装客户端的原生目录。
- **优先级顺位编排**：每个顺位新增"选择客户端 / 模型"，可选择执行器、搜索并选择其模型与思考强度。
- **四张原生额度卡**：WorkBuddy、ZCode、OpenCode Go、CommandCode。
- **"额度与同步设置"**：手动刷新、开启可见页面自动刷新并设置间隔、以及连接/来源设置。数值由所选来源读取。

关于可选档位：列表只显示提供方/原生客户端**实际声明**的档位；无法判定时按默认档位处理，不做推测。

关于目录查询：部分提供方会拒绝目录查询（例如返回 HTTP 403）。这类错误会如实显示，已保存的模型行仍可继续选择。**目录可见不等于账号权益、剩余额度或能力校验**。

## 二、配置现有连接

1. 对 API / 本地连接，在执行端“参数设置 → 模型与连接”中添加或编辑连接，核对服务类型、Base URL 和模型 ID。
2. 对需要 Key 的 API 连接，填入或编辑该连接的 API Key。编辑时**留空表示保留原 Key**；填入新值才会替换。
3. 保存后，卡片与模型选择器即可使用该连接。

WorkBuddy / ZCode 使用各自的桌面登录账户，在参数设置中连接自己的安装和用户目录/桥接；不填写 API Key。OpenCode / CommandCode 需另行安装指定版本，并在参数设置中配置 CLI 路径及自己的账户连接。版本和工具范围见文末指南。

说明：

- 既有注册表中的 API Key 仅供内部调用，界面**不会显示原始 Key**。
- **不会自动导入**客户端自身的认证数据库。
- 安装与账号由使用者自行准备；新装环境中工作台不含任何用户模型或 Key。

## 三、更换某张卡片的当前模型

1. 点击卡片上的"当前模型"区域，打开搜索选择器。
2. 用名称 / id / 来源搜索，或按来源过滤缩小范围。
3. 选中目标模型（含思考强度，如该来源声明了档位）。
4. 点击"应用模型"，该卡片的当前选择即更新，**对之后新建的任务生效**。

可选：勾选附加复选框，可同时把该模型写入此执行器的**自动候选**列表。

注意与顺位模式的区别：卡片上的"应用模型"会真正改变卡片的当前选择；优先级顺位中的选择只写入草稿，需最终"保存"才落盘（见下节）。

## 四、按顺位编排客户端与模型

1. 在某个优先级顺位点击"选择客户端 / 模型"。
2. 选择执行器，然后搜索并选择它的模型与思考强度。
3. 点击"用于此顺位"——**此时仅更新草稿**，尚未保存。
4. 全部顺位调整完毕后，点击最终"保存"。

保存语义：

- 保存会**批量写入新的不可变模型变体**并记录顺序；各端点的当前模型默认值**不受影响**。
- 每个顺位都会显示所选客户端、模型与思考强度。
- 支持移动、新增、删除顺位，并**保留空位**。
- 选择了一个已被其他顺位占用的已保存模型时，两个顺位**互换位置**。
- 轮询会保留草稿；若期间策略或来源发生并发变更，过期保存会被拒绝。
- 写入失败时，模型与顺序**回滚**。
- 取消或重置不写入任何模型设置。

行为边界：保存顺位不会改动排队中或运行中的任务，也**不会自动重发**失败任务；模型选择本身**不启用**引擎，也**不改变**云端权限或预算。

## 五、额度查看与同步

1. 四张原生额度卡分别显示：剩余量 / 百分比、重置时间或到期时间、来源、最后更新时间。
2. 在"额度与同步设置"中可：手动点按刷新、开启可见页面自动刷新并设置间隔、调整连接与来源。
3. 切换额度来源会使旧的账号显示**失效**（数据不再代表新来源）。

判读要点：

- "未知""错误""数据过期"与"额度为 0"是**不同状态**，不要混为一谈。
- 额度与目录都只能读，读取**不会触发生成**。
- OpenCode 的免费通道与 Go 账号是分开的；并非所有服务都提供余额信息。
- 原生聚合额度与 token 统计**不能证明**请求次数或单任务的 RMB 成本。

## 六、支持版本、验证边界与排障

支持版本：

- OpenCode 适配器面向 CLI 2.1.3（ACP 接受已复核的 2.1.3 / 2.1.4）。
- CommandCode 面向 1.86.1，**精确版本**匹配；其元数据加载器还会校验随包源码哈希。
- OpenCode / CommandCode 以精确文件清单为守护范围：该守护下**不开放终端、不启用子代理、不做会话续跑（continuation）、不授予全权限（full access）**。
- WorkBuddy / ZCode 的元数据与额度桥接仅走本机回环。

验证边界：

- 未对全部模型做过测试，也不保证任何服务的额度"永久免费/无限"。
- 宿主原生菜单的可见性未自动验证。
- 新安装不含预置模型/Key，默认顺位顺序不会自动填充。
- 原生逐请求金额/次数无法核实时，开启这类硬上限会拒绝原生执行；工作台不会替你关闭上限、放宽付费许可或取消既有任务。
- 版本相关的内部实现可能在上游更新后需要重新适配。

排障清单：

1. **模型列表为空或报错**：先看是否有目录查询被拒（如 403）。可改用已保存的模型行；错误不代表账号无权益。
2. **额度卡显示未知/错误**：确认客户端是否运行、来源选择是否正确；切换来源后旧的账号数据会失效属预期行为。可尝试刷新或修正来源。
3. **WorkBuddy / ZCode 元数据或额度取不到**：这两个桥接仅走本机回环。若现有客户端缺少桥接能力，请自行保存工作、**完全退出**后重新连接。
4. **保存被拒绝**：多为期间策略或来源发生变更，重新载入后再编辑；若写入失败，模型与顺序已回滚，草稿可继续调整。
5. **顺位改了但任务没变**：顺位选择在保存前只是草稿；即便保存，也不影响排队中/运行中的任务。
