## 能做什么

通用项目可在根目录提供 `project-architecture.json`，由项目维护者或 Agent 保存中文职责、产出、关系及代码 SHA-256 依据。地图查询沿用项目绑定读取说明，每次独立核对元数据和受限代码快照；代码变化、依据未收录或文件格式错误均明确标记。业务讲解是作者声明，哈希相符不等于语义或运行流程已验证。格式、生成步骤及限制见 [Agent 架构讲解指南](PROJECT_ARCHITECTURE.md)。普通打开不自动调用模型或写入说明。

工作台“当前项目”旁的“项目地图”打开只读弹窗。默认的“项目概览”展示可交互架构图，点击中文模块可查看职责、产出、关联模块和对应代码，点击代码可进入原有细节页。支持键盘选择并保留焦点；连线随容器宽度重新定位，窄侧栏自动折行或纵向排列。

识别到本项目根 `.local-worker/` 下的一组核心实现文件时，展示人工整理的协作讲解图：用户与主脑提出需求 → 控制器安排任务 → 执行 Agent 执行与自测 → 主脑独立验收，并画出退回整改回路。工作台与任务记录是全程可查看的状态层，派发、执行、验收分别汇入；不能把它理解为验收之后才产生记录。讲解连线表示职责与产品流程，不是从静态导入推导出的逐步调用链。发布副本或其他目录中的同名文件不会触发该模板。

其他项目展示按路径推断的中文模块，连线只来自本次索引中真实识别到的跨区域静态导入，不套用本项目的任务流程。没有导入证据就不画箭头。模块归类不能代替项目文档或自动业务理解，JS/TS 等未解析依赖的关系仍可能缺失。当前页面可见任务数量仅统计选中项目，不表示验收通过；未加载的任务和未收录文件不会被补造。

“代码细节”保留原有搜索、文件/符号、静态关系图、相关测试和快照哈希，供需要核对实现的人按需展开。提供“直接关联/全部关系”切换和刷新；窄侧栏使用上下布局。只有选择明确项目才能打开，未绑定或“全部项目”视图不扫描。概览和细节共用同一只读索引，打开页面不调用模型。

地图使用当前所选项目，并非固定展示框架自身。打开、刷新或主动查询时才扫描；普通工作台轮询不触发地图扫描。切换项目、关闭弹窗或更新请求后，旧响应作废。地图不派发任务、不调整设置、不替用户验收，也不自动将图中关系扩展成执行文件权限。

## 给主脑查询

- Codex 默认工作台 MCP：`query_project_map`。可以显式提供可信调用项目的 `project` 绝对目录；省略时沿用当前聊天目录/唯一 MCP root 的解析规则，未知则拒绝。这个入口直接调用公共索引，不依赖工作台后台或额外模型。
- 通用 brain MCP / DSH：`brain_project_map`。先按原流程连接；项目固定为启动时绑定的可信项目，工具参数不能更改项目、owner 或会话。
- 两个入口共用 `.local-worker/project_map.py`。读取工具与协作开关独立，不派发任务；关闭协作不阻止只读导航。已有常驻 MCP 连接需重新加载工具；不自动重启宿主。

常用参数：

```json
{"query":"router","limit":20}
```

```json
{"file":"src/router.py","limit":40}
```

`query` 搜索已收录路径和符号；`file` 只接受当前索引内的相对代码路径，返回该文件及直接邻居；`refresh=true` 强制重做解析。绝对文件路径、上级跳转、未收录文件和覆盖项目身份的字段均拒绝。

CLI 不需要服务，可用于已有聊天尚未加载新 MCP 工具时的同一项目只读查询：

```powershell
python .local-worker/project_map.py --project <可信项目绝对目录> --query router --limit 20
```

工作台页面通过现有带项目视图及会话校验的 `POST /api/project-map` 使用同一索引；Codex MCP Apps 将新增 JS/CSS 一并内联，不放开外部资源。

## 关系与证据边界

Python 关系通过 AST 提取 `import/from`，附来源文件行号。别名和相对导入按文件结构解析；项目根匹配、相邻目录、约定的 `src` 目录与祖先目录候选分别标注。路径候选尚未核实运行时 `sys.path`。歧义、外部模块和动态导入列为未解析，不挑一个目标假装确定。

JS/TS/PowerShell 首版复用已有符号提取器，仅显示文件/符号；尚无它们的依赖解析。不加载、导入或执行项目代码。正则解析的签名不展示默认字面值；其他派生字符串沿用现有脱敏规则。

相关测试只表示“该测试静态导入此模块”，不代表覆盖率、执行或通过。任务/验收记录、运行时调用链、自动影响分析、按任务自动选择上下文与一键打开原文件均未接入；文件路径和行号目前用于手动定位。

## 扫描、缓存和限制

- 复用 `context_manager` 的符号解析与默认排除策略，另排除宿主私有目录、工作台临时任务/安装资料。默认不扫描记录、认证、依赖、缓存和媒体，不返回文件正文。
- 跳过文件/目录链接、Windows reparse point 及真实路径越界；这是应用层检查，不宣称操作系统沙箱或能抵御任意并发恶意改链。
- 默认最多 300 个代码文件、每文件 512 KiB、合计 8 MiB 读取量、目录枚举 20000 项、扫描发现阶段 5 秒。每文件最多展示 24 个符号，关系最多 2500 条，未解析项最多 300 条。限制、跳过及符号截取在响应/界面中提示；未收录不表示不存在。
- 图形最多展示 40 个节点，文件列表仍可搜索和选择本次返回的其他节点。模块图不是完整仓库的承诺。
- 不写项目索引、Git、`.model-desk` 或其他项目文件。最多缓存四个项目的解析结果于当前进程内，每次查询重新扫描并核对受限内容哈希后才能复用，包含增删和同大小/时间戳的内容变化。进程退出即丢失缓存。
- `index.hash` 只代表本次受限快照。刷新不能绕过既有排除和数量上限。`freshness=partial` 或任何截取标志表示覆盖不完整，不能解释为项目不存在相关代码。
