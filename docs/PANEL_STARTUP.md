# 工作台启动与连接诊断

Codex MCP 与 DSH 原生入口共用 `panel_startup.py`。只有明确打开工作台或首次 UI 会话请求会启动服务；导入、工具列表、普通查询与预检不启动服务或模型。已有业务请求的网络失败不会导致重派。

就绪检查使用 `GET /api/ready`，只返回服务标识、就绪标记、安装目录及请求视图。它保留 Host/Origin 校验，不读取模型、账户或任务汇总，也不返回会话 token。安装目录必须与启动入口一致；其他安装或无法确认的端口不会被停止或替换。旧后台仅在该端点返回 404 时做一次有界 `/api/state` 兼容检查；脚本直接打开旧后台时请先升级后台，不能把身份未知当作启动成功。

一次启动的锁等待、探测、启动器和最后确认共用 32 秒预算。原生启动器最多 28 秒，其脚本获得更短的剩余预算；脚本跨进程互斥锁覆盖创建与就绪确认，避免同时打开产生重复后台。Codex 的 45 秒通信期限和 DSH 的 50 秒期限均有余量。超时后只有再次确认同安装后台已经就绪，才返回成功；不会杀掉后台或自动重复创建。

错误区分 `startup_busy`、`launcher_timeout`、`spawn_failed`、`launcher_exit`、`foreign_installation` 和身份/探测未确认。界面只接收受控分类，不转发原始进程输出。后台日志在本安装的 `.local-worker/panel.stderr.log`；可手动运行 `打开模型工作台.ps1 -NoBrowser` 查看启动器的本机诊断。不要把日志或账户配置公开粘贴。

更新后，常驻 MCP 进程需要重新连接才能加载 Python 改动；刷新页面不能重载进程代码。DSH 每次明确打开时执行公共引导程序，无需因此替换插件包。临时安装冷启动、并发复用与模拟异常测试不代表已在每个桌面宿主点击验收，原生呈现仍需分别确认。
