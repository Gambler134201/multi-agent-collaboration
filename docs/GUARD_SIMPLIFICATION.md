## 已确认并修复的过度判断

原生终端规则多次扫描同一命令文本，把数据当成操作。例如 `Write-Output "git commit and .model-desk"` 只是打印文字，WorkBuddy/ZCode 却按 Git 操作拒绝；输出原项目的绝对路径也会触发工作区隔离。真正访问目标不存在，后续的整轮暂停因此没有必要。

公共 `record-policy.terminalAnalysis` 现在只识别**整条字面输出调用**（echo / Write-Output / Write-Host 的有限公共语法），向后续记录保护、项目隔离、原生权限扫描提供统一分析文本。输出负载不再分别充当路径、Git 动作和递归删除目标。原生工具仍收到原命令，回执哈希仍对应原命令；不增加工具执行层，不执行分析文本。

未识别语法逐字保留原分析：变量、命令替换、转义/拼接引号、单引号、重定向、复合调用、无引号通配符、超长输入均不获得新豁免。真实 cwd/workdir、只读任务、工具白名单、后台请求、沙箱绕过参数与此前拒绝状态仍独立检查。这里的公共语法不证明任意脚本安全，也不依赖工具叫 Bash 就推测解释器。

一项旧 fixture 曾把“echo 输出受保护路径也拒绝”编码为期望，本批明确修改该行为并保留真实 cat/read 拒绝对照。未接线的 junction 路径候选也不能重新扫描已识别的输出负载；新增兼容反例记录这一约束，候选本身仍未接线。

## 哪些检查保留，哪些需要继续收敛

| 机制 | 当前判断 | 后续处理 |
|---|---|---|
| 任务/project/session/job/proof 身份、保护版本校验 | 有必要；避免错会话或旧配置冒充有效保护 | 保留，不因减少错误而跳过；不静默升级旧任务 |
| 项目范围、原项目/其他任务隔离、记录/认证保护 | 目标不同，不能因多层就全删 | 统一分析输入，保持权限与隔离的不同职责 |
| 多处对 Shell 全文做关键词/路径扫描 | 有已复现误拦，不能当可靠执行语义 | 本批先消除字面输出负载的重复判断；其他复杂语法仍需成熟解析组件和方言证据 |
| 普通原生工具错误 | 不应自动升级为保护拒绝 | 现有缺失文件/非零退出回归继续保留，让原生 Agent 自行纠正；旧限定工具模式另列兼容限制 |
| 真正的保护拒绝后暂停 | 防止换工具绕过有必要，但错误检测会放大影响 | 优先纠正拒绝依据；不能直接关掉暂停或自动重派 |
| 自测精确命令哈希 | 有严格性成本；它证明执行的是指定命令，不能只信模型自报/exit0 | 原始失败不改写；未来若支持等价命令，须有可核实调用语义，不能删空白/引号后盲目认定等价 |
| 验收、收尾、请求结果未知 | 三种不同证据状态 | 保留分层；不把验证不足当模型质量差，也不因会话关闭解除未知请求重发限制 |

## 仍待统一：工具拒绝与整轮状态

`test_pi_runtime.test_tools_record_guard_and_relay_usage` 证明：Pi 的记录写入被实际拒绝，后续写入暂停，但原生 Agent 返回最终答复后，现有 worker 仍可记录 `completed`。WorkBuddy/ZCode 则读取拒绝标志，把相同类别记为整轮失败。两者都不能替代独立验收，当前产品表现却不一致。这个差异不是本批新引入，也不能因为减少失败数就把所有拒绝改成成功。

下一批应先定义共同契约：原生回合是否结束、哪些动作被拒绝、交付是否存在、必需目标是否完成、独立验收是否通过分别记录；保护拒绝保持阻断，普通工具错误仍可由原生端纠正。然后对四端与 Codex/DSH 状态、交付、通知做对称检查。不得自动解除现有拒绝状态、补派旧任务或伪造成功。

这比继续增加新框架、工具实现或不透明重试更优先；成熟解析组件用于减少对文本的误解，不是再加一套审批模型。

- Node 七文件增量：runner 报告 61 项通过（其中记录保护文件另含 25 个内部断言组，不把它们重复相加）。包含 ZCode hook 原输入不变、无拒绝标志、原命令哈希不变及未接线候选兼容性。
- Python：WorkBuddy 原生工具 39 项通过；ZCode 原生工具/工作区绑定/记录保护/权限四套件 73 项，72 通过、1 项可选安装预设检查跳过。安装版 Pi 接本地模拟提供方的 3 项通过，包含字面输出后的正常写入与真实越界/记录写入拒绝。无真实模型请求。
- DSH 运行时检查**未通过启动条件**：先缺显式安装位置，补临时进程环境后仍缺源码工作区 acpx 依赖，尚未加载到工具。为测试建立依赖目录联接被自动审批检查拒绝（仅返回 blocked by policy，无具体原因）；未换工具重试，未创建该联接。这些启动失败不能当作守卫行为失败或通过。新增运行时输出 fixture 尚待具备依赖的环境验证。
- 无全量回归、运行版部署、两宿主 GUI 或新增 WorkBuddy/ZCode 真机生成验收。保护指纹自动改变，只对加载候选的新任务生效；旧任务不迁移。不能声称整体误拦率已经下降或四端真机已全部通过。
