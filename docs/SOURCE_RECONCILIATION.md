# 开发源码与公开版整合

本分支 `chore/source-reconcile-dev` 从公开 `main` 的 `cb174f8` 创建，先建立开发规则和待整合清单。当前已把审查后的每模型默认 Agent、按需目标进度/只读历史目标及对应离线检查迁移进来；没有整段合并本地快照历史。

## 保留的两个真实基线

- 公开基线：`main` / `origin/main`，初次 MIT 发布；包含可移植运行时路径、安装脚本与安装测试。
- 本机基线：本地分支 `baseline/local-2026-10-18`，提交 `3774162`；保存近期每模型默认 Agent、首页目标精简及本机运行源码。原发布历史另有本地 bundle 备份。

本机基线只用于对照与恢复，不能将其整段历史推送或合并到公开分支。公开整合应在当前分支迁移必要代码，逐项查看差异及隐私内容。

## 整合顺序

1. 保留公开版 `runtime_paths.py`、环境变量配置、干净安装默认关闭协作与付费、规则模板绑定、`setup.ps1` 与现有安装测试。不能用本机固定路径覆盖这些能力。
2. 迁移每模型默认执行 Agent 的后台、路由、已有会话保持原 Agent 及相关测试；模型/密钥/预算记录留在原项目，不能复制。
3. 迁移每模型 Agent 快捷入口和目标进度按需展示，保留已有项目绑定、记录删除门禁与观测功能；使用 mock 浏览器检查。
4. 把新增检查脚本的本机工具路径改为可配置/可发现的依赖路径，并保留全部有意义的断言；把操作说明中的本机路径整理为实际安装目录的模板。
5. 复核本机全量回归暴露的两项通知不稳定场景：并发注册的项目路径校验已复现并修正；隐藏监听测试结束时日志句柄占用在修正后完整回归中未再出现，但仍需保留观察，不能把定向通过当作唯一根因已证明。
6. 运行安装回归、相关 Python 与前端回归并独立审查；确认没有错误删除公开能力后，形成可合并差异。多主脑通用接口的开发从验收后的整合基线继续。
7. 真正发布时重建源码清单/归档、验证全部新增历史的隐私内容，再按授权推送与提交 PR。现有 `SOURCE-MANIFEST.json` 是初次发行校验清单，不能当作后续开发分支的完整文件清单。
