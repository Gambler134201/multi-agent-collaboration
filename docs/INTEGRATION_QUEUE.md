## 首版顺序

1. 先持久化提交意图：同一项目、同一目标、已接受并结算的任务、精确冻结提交、基线和检查参数。原请求重复只返回同一作业，不重建副本。
2. 复用现有项目集成租约执行，持久呈现排队、准备、合并、检查及终态；相同名称的并发调用不能利用租约重入重复执行。
3. 成功仍需原主脑独立验收；冲突、检查失败和执行未知保留现场，不自动整改、重跑、覆盖原树或更新 main。
4. 服务重开可查询原作业。尚未开始的作业可显式继续；已经开始但结果不明时只核对，不自动重跑或释放其他占用。原主脑授权不写入磁盘，重开后需同一责任连接重新提供授权。
5. Codex/DSH 使用相同后台和界面；任务关系图、任务详情可以进入集成详情，查看真实输入、检查及阻塞原因。页面查看不派发模型、不自动提交集成。

## 验收重点

临时 Git/记录和模拟检查覆盖同项目串行、重复请求、冻结输入漂移、冲突、检查失败、检查改成果、进程中断、原请求查询、取消与领取竞争、归属及项目隔离。界面覆盖两种宿主、空记录、过期/错误数据和只读动作。优先增量检查，不用真实账户或退出应用制造故障。

首版不承诺恢复任意检查脚本遗留的后台进程或消除操作系统隔离限制；未知现场需要明确核对，不用超时或字符串猜测解锁。

## 已实现的入口

分支 `codex/integration-queue-20261027`，基线 `9c69ec5`；**源码候选，未部署**。项目操作区的“集成队列”显示真实任务、冻结提交、基线、检查参数及实际退出码/输出、冲突文件和保留副本。任务详情与关系图可打开原集成记录。同一页面资源用于 DSH 网页和 Codex 内联面板；沿用原刷新链，没有新定时器。查询只读，没有记录与读取异常分开，切换项目丢弃过期回复。

保留同步 `brain_integrate(request_id, task_ids, checks)`，可选 `enqueue=true` 先持久入队。例如：

```json
{"request_id":"integrate-approved-1","task_ids":["accepted-task-a","accepted-task-b"],"checks":[["node","--test","test-combined.cjs"]],"enqueue":true}
```

任务仍须同项目、同目标、同责任身份、已独立接受且已收尾。返回 `integration.name` 与 `integration.queue.state`。入队请求 `completed` 只表示计划已保存，不表示检查或验收完成；`brain_request_status` 查询原 request_id 返回当前原作业及只读 `integration_status`。检查通过后仍需主脑检查实际成果，使用不同 request_id 调用既有 `brain_accept_integration`，不会自动接受、更新 main 或覆盖原树。

重开服务先查询原请求。只有**已确认完成入队且原作业仍 queued**，才能明确重复完全相同的 request_id 与参数续接同一个作业。unknown/reserved 请求、已开始或结果不明的作业不得据此重发；`safe_to_redispatch=false` 保持。Authority 只在进程内，不写记录/提示词；其他聊天不能收养。

普通本地控制器任务可在面板明确确认后继续/取消未开始作业，运行/未知作业仅提供核对。**绑定主脑的作业在面板只读**：继续需原主脑重连接续；取消/收尾核对目前只有持有有效 Authority 的控制器接口，尚无新增的正式主脑取消/核对工具，页面不假称支持。

控制器复用 `integration_queue.enqueue/schedule/get/snapshot/cancel/reconcile`。项目绑定 HTTP：GET `/api/integrations`、GET `/api/integrations/<name>`；POST `/api/integrations`；POST 原名称的 `/resume`、`/cancel`、`/reconcile`。沿用面板会话与项目约束，body 不能覆盖项目、权限或原检查计划，普通面板不能修改主脑归属任务。

## 持久化、锁与恢复边界

- 原记录 `.model-desk/integrations/<name>.json` 增加意图及进度，包含请求引用、任务/提交、基线、检查计划。沿用最多256份、单份1MB的有界读取；超出/损坏显示不可完整核对，不清空队列。哈希用于发现输入变化，不是对抗任意本机写入的密码学凭据。
- 注册到既有面板线程池；同项目已授权队列按入队时间选取，集成和验收共用原 integration 租约，每次调用使用独立持有者。锁延长至最终回执落盘，避免结果未保存时其他调用抢入；不同项目不共用这把锁。
- 领取与进程身份先落盘，再创建副本/合并/检查。输入漂移等执行前失败记录 blocked 并释放本次锁；领取后缺完整终态则 recovery_required，保留现场与租约。冲突/检查失败/取消不自动重试或整改。
- 导入和读取不启动泵，服务重开不重造授权/自动续跑。另一进程释放占用不保证唤醒本进程，必要时显式续接原 queued 作业。运行态进程已退出或不可核实时，只读投影提示待核对，不悄悄改原回执。
- `reconcile` 只核对原进程并记录待恢复，不合并、不运行检查、不释放未知租约。任意中断后的自动恢复、遗留检查子进程确认、终态落盘后崩溃留下的租约回收仍待后续；首版没有强释按钮。检查命令复用既有参数向量执行器及超时，不派发模型、不改写 Shell、不改变权限。
- 同步旧记录继续可读，包括合法带点号名称。新队列不改旧任务/用户设置、不推进下游或接受集成。
