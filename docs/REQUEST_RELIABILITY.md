# 请求回执与只读结果查询

2026-10-23：源码修复已完成，DSH 0.2.12 已在本机安装并核对八文件哈希及安装收据；用户随后转述的原生 DSH 会话结果确认新工具已加载、完整 JSON 可读，未派发任务或重试旧任务。

## 修复内容

- 操作后保存完成回执、异常恢复回执或明确拒绝回执失败，都不会再以普通 HTTP 400 冒充确定拒绝；返回 unknown 和原请求引用，不自动调用第二次模型。
- unknown 标记也保存失败时，仍返回 unknown；已提交的 completed/rejected 回执不会被晚到的 unknown 覆盖。
- 新增正式 `brain_request_status`，查询本连接的可信项目、owner/binding 对应的原请求，不修写请求或任务，不等待执行器，不派发模型，不初始化空项目。
- 移除“权限”“预算”单词触发系统故障的过宽匹配；有已完成交付的权威验收优先于历史错误文本。文本推断保留兼容原因，但明确 `verified=false`，不伪装结构化证据。

## 使用

连接主脑 broker 后调用：

```json
{"request_id":"原来那一次派发使用的编号"}
```

工具名：`brain_request_status`。不能传入项目、owner、宿主或会话来扩大范围。

| request_state | 含义 |
| --- | --- |
| completed | 请求日志已完成且关联任务归属可核实；任务本身可能仍在排队/运行，并不表示独立验收通过 |
| task_found | 原任务可核实，但日志可能 reserved/unknown/缺失；可用返回的 task_id 读取状态/交付，查询不改日志 |
| reserved | 原请求已保留、尚未找到可核对任务；可能仍在处理中 |
| rejected | 原日志记录明确拒绝，且没有相冲突的关联任务 |
| unknown | 记录损坏、不一致、歧义、不可读或无法确认；不挑选其中一条，也不重派 |
| not_found | 当前责任范围没查到；不证明没有执行，也不允许换 ID 重派 |

始终返回 `read_only=true`、`automatic_retry=false`、`safe_to_redispatch=false`。日志原状态通过 `journal_state` 表达，避免将“找回了任务”误读成“已修复日志”。不返回原提示词、完整回执正文、数据库异常细节或连接凭据。

查询同时限制项目与原责任会话。同项目新聊天即使被允许读取历史任务，也不能凭 request_id 查询其他 owner/binding 的私有请求关联。若有合法跨会话接管需要，另走显式策略，不通过本工具自动收养。

## 主脑入口边界

该工具在宿主中立的 brain MCP 中提供，Codex/DSH 身份共用 broker、参数与响应投影；DSH 插件接入对应白名单及用法提示。离线检查覆盖两种宿主身份的真实 stdio→HTTP→临时记录链路，并可用已安装 DSH 客户端代码检查模型可见文本。

Codex 当前默认工作台 MCP 仍是 `open_model_desk` 与界面代理，普通 CLI 派发并不因此自动拥有 broker request_id。只有走正式 brain 请求通道的任务可使用本查询；既有 CLI 任务仍按原 task_id 查询，不能把该工具说成所有旧任务通用入口。加载新工具可能需要新建/刷新 MCP 连接；不自动重启宿主。
