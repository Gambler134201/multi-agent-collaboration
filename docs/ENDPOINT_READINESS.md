# 执行端就绪诊断

2026-10-28 源码功能说明。后续已将仅含本批的12文件包部署到日常版，未合并 main、未推送；本页原源码验证与[实际部署记录](ENDPOINT_READINESS_DEPLOYMENT_20261028.md)分开。

## 用户看到什么

“已启用”只表示允许接收新任务，不能证明安装、连接、模型及授权都可用。卡片保留紧凑布局，分别显示当前本地预检结论和任务活动；“查看诊断”打开参数弹窗的“就绪诊断”页签，列出具体原因与处理建议。普通“参数设置”仍先打开“能力与成本”，切换页签及刷新不丢失未保存的预设草稿。

| 显示原因示例 | 表达的事实 |
|---|---|
| 执行端已禁用 / 协作总开关已关闭 | 设置阻止新自动协作，不是安装故障 |
| 缺少安装配置 / 安装文件缺失 / 版本尚未适配 | 当前安装信息不足，不自动换执行端 |
| 原生通道未就绪 | WorkBuddy 的同配置目录通道未能唯一确认；账户授权尚未核实 |
| 桌面未开启桥接 | ZCode 已打开但没有可用桥接，需要用户在任务结束后自行处理 |
| 原生通道待核对 | 桥接或进程状态未知，不当作桌面已退出 |
| 模型列表需更新 / 已选模型不可用 | 缓存或保存的选择不适用，不自动替换模型 |
| 模型被范围排除 / 缺少付费授权 / 原生用量无法满足硬上限 | 与安装状态分开解释，保留用户范围与限制 |
| 可自动连接 | ZCode 桌面确认缺席、有效缓存及已保存自动连接设置允许任务前连接；此时尚未连接 |
| 本地预检通过 | 只证明本地预检，不能证明账户授权、模型服务、资源占用或任务成功 |

多个已知问题同时存在时，卡片显示首要原因，诊断页列出其余问题。安装位置、版本、原生模型选择仍在“模型与连接”管理；诊断不代用户修复配置、初始化通道或发送普通对话。

## 共同实现与边界

- `endpoint_readiness.py` 是纯投影：接受设置、模型和适配器事实，生成固定原因码、中文说明与建议，不读文件、不请求网络、不调用模型、不保存设置。原因来自适配器已知失败边界，不从整段异常文本猜测。
- 四执行端的 `availability` 提供本地事实；`execution_engines.public_availability` 将异常的展示探针降为未知，避免一个卡片拖垮整个状态页，不把原始异常带进新诊断字段。它不替代真实 worker 的执行错误处理。
- `execution_endpoints.public_rows` 合成共享诊断；Codex/DSH 的正式候选使用同一投影与开关快照，只增加精简的执行端摘要，不重复原生目录、额度缓存及整份模型列表。既有预检通过候选读取该新增字段，无新增正式工具。
- Codex 内联资源和 DSH 网页使用同一页面代码、弹窗与原因说明。没有新增接口或调用白名单，无本批 DSH 包版本变更；此前 0.2.17 仍是另一批收尾修复的源码候选，日常插件仍为 0.2.16。
- `diagnostic.precheck_passed` 与原 `ready` 分开，不改变已保存开关、模型、范围、权限、预算、派发规则和既有任务快照。诊断包含自动路由及总开关约束，不能据此概括所有显式手动操作。

本批修正两个读取问题：ZCode 可选额度缓存损坏不再清除已成功核对的执行通道；桌面状态读取未知不再显示“可自动连接”。实际 `connect` / `ensure_connection` / 启动路径未在本批改造，不能把展示预检收紧称为完整生命周期修复或真实自动连接验收。
