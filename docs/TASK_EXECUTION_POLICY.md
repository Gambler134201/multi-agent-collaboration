## 2026-10-27：自主工作是日常默认

普通新任务省略 write_scope 或使用 workspace，预期交付文件只用于说明与验收；主脑不得仅为分工、缩小 diff 或减少审查范围，自行启用 declared_files、建立限定文件阶段或在提示词写“只能修改这些文件”。执行端可以在已保存访问范围内创建必要源码、测试、脚本、交付说明与临时材料，不因未列在预期清单而拒绝。

## 职责

工作台在任务开始时确定目标、项目、执行端/模型、已有访问权限和明确限制。原生 Agent 在该边界内自行调查、实现、创建辅助文件、运行测试及纠正常规错误。工作台负责必要保护、原请求与会话身份、异常监控、定向收尾和独立验收；预期交付清单不再默认充当写入白名单。

已落地交付与权限分离、集中声明保护路径，以及普通工具错误/真实拒绝/自测证据不足的状态收敛。最新新任务使用 schema=3：终端取消全文提词式硬拒绝，采用有限直接目标核对；旧版本保留旧行为。四端真实任务、宿主 GUI 和部署仍分项验证，不能称整个架构已完成验收。

## 请求与快照

| 字段 | 含义 |
|---|---|
| `files` | 新原生 edit 任务的预期交付清单，0–30 条；可留空，不要求预先猜出辅助文件 |
| `write_scope` 省略或 `workspace` | 沿用已保存的 project/full 访问权限自主处理普通文件；不改变访问模式、账户、费用或模型 |
| `write_scope=declared_files` | 调用方明确要求限定文件，files 不得为空 |
| `readonly_files` | 项目内已存在的明确只读文件；即使也列入交付清单，仍不得由文件工具修改 |
| `task_policy` | 控制器生成的新 schema=3 快照：write_scope、home 与 deny_paths；请求不能直接提供 |

chat 快照固定为 read_only，不接受写入范围请求。阶段已限定文件时保持限定；续接/整改继承父任务，不按新默认放宽。历史记录无快照表示 legacy，不等于 workspace；畸形快照拒绝执行，正式读取显示 invalid。

schema=1 是首批契约；schema=2 增加声明路径但保留终端全文扫描。两者仍按原规则执行，不自动补成 schema=3。schema=2/3 的 home 是解析 `~/` 的控制器声明路径，deny_paths 是任务创建时确定的绝对保护位置，不包含认证正文。正式状态/交付仅返回 schema 和 write_scope，不投影本机私有位置。整个快照参与原生 job、连接证明和验收身份绑定，删掉保护路径或改版本不再是同一个任务授权。

## schema=3 的终端边界

四端共同使用新策略；Codex/DSH 经同一控制器创建快照。结构化文件路径、cwd/workdir、权限及链接检查保留。终端不再把任意引号内容、检索式、过滤值、程序输出或脚本文本当访问目标；不能识别的语法不产生保护拒绝，也不把它标为已验证安全。

有限直接调用包括 cat/Get-Content、ls/Get-ChildItem、rm/Remove-Item、Set-Content/Add-Content/Out-File、cp/mv 等及字面 cd 链。只有明确的路径位置接受核对，Set-Content 的内容与 -Exclude/-Filter 等值不当路径。明确敏感目标、删除记录/Git元数据上级、结构化只读/限定文件、项目范围及原项目/其他工作区仍受检查。直接 git push/commit 等受限操作仍拒绝；带其他选项或复杂语法的 Git 命令不保证可识别。

变量展开、通配符清理、管道、重定向、脚本/外部程序及未支持语法的 IO 不从文字推断，不触发旧的“无法核实即拒绝”。这会减少启发式拦截覆盖：例如不能保证动态脚本无法读写敏感文件、范围外文件或修改 Git。项目范围与严格文件范围均不得称为覆盖任意脚本的硬隔离；原生权限、任务要求和独立改动检查仍必要。强制隔离仍后置。

原生命令和事件哈希保持原文；不执行分析结果、不新增工具、不自动重试。真实保护拒绝继续暂停本轮，结果未知、收尾未确认与自测证据不足仍分别处理。旧队列、续接、整改和已有失败不改写，保护指纹变化时旧连接按既有规则拒绝静默换版。

**主脑必须把用户的明确限制转换为结构化约束。** “只能改 a.py”应传 write_scope=declared_files；仅提供 files=["a.py"] 在新契约中表示预期成果，不再替代明确授权范围。提示词中的其他用户要求仍有效。

Codex CLI 提供 `--write-scope declared_files`、`--readonly-files ...`；正式 brain_dispatch 提供同名字段。新参数参与原请求内容校验，同一 request_id 不能换范围。任务窗口提供文件约束选择，续接显示并锁定原规则；两主脑正式状态/交付共用权限视图。

## 执行与保护

Pi/DSH 与 WorkBuddy/ZCode 共用 record-policy.taskWriteReason 的文件范围判断。workspace 不再逐文件核对交付清单；declared_files 和只读限制独立执行。既有访问模式、记录、其他任务、副本原树、认证与原生配置保护继续运行。普通缺失参数交由原生工具报告，不自动污染任务拒绝状态。

schema=2 通过同一 protectedArgumentsReason 匹配明确路径和已解析的别名：用户目录下的已知认证/原生配置、当前控制器私有文件与历史材料、原生适配器已知的自定义配置根，以及项目根的原生 hook 配置。Codex 数据目录可能包含源码 worktree，只保护其已知认证、会话、日志和状态文件，不封锁整个父目录。目录本身不必存在；声明不会创建或读取认证文件。保留 `.model-desk`、`.git` 与 `.env` 的特殊目录/文件约定。

普通业务 `tokens.json`、`auth.json` 或名含 auth-token 的测试不再仅因名称被当成认证访问。新原生目录搜索也从路径声明生成排除规则，不再全局隐藏这些业务文件。schema=1 和无契约任务继续原规则，不静默换版。文件与终端字面路径共用匹配，必要删除操作还检查是否覆盖受保护根的上级；普通输出、搜索词不是授权依据。

这只统一已声明位置的目标检查，不代表所有认证位置自动发现、所有递归工具结果均隔离或四端原生能力已等效。任意脚本、运行时展开、外部程序与文件系统竞争仍不能由参数守卫证明安全。原生账户自定义目录须由适配器提供，未声明的敏感业务文件仍需任务只读限制或既有访问权限，不能把名称识别当秘密扫描器。

快照进入原生 job、DSH/Pi 会话身份和保护证据；WorkBuddy/ZCode 加载器核对控制器记录。验收绑定包含快照，验收后改范围不能保留原接受结论。保护指纹变更后旧任务/连接仍拒绝静默换版。

这是**原生文件工具参数级约束**。本批不增加 Shell 解释器，不能证明任意终端脚本计算出的写入范围；明确范围还需要原生 Agent 遵循及主脑检查实际改动，不能称为 OS 沙箱。新强制隔离系统后置。

## 任务结束、自测与验收

| 证据 | 源码候选的处理 |
|---|---|
| 普通工具报错，原生 Agent 随后正常结束 | 不因历史工具错误把整轮改成失败；执行器可在同一任务内修正 |
| 已绑定保护层确实拒绝调用 | 四端均保留失败；Pi/DSH 新 proof 保存首个固定拒绝码，不按模型答复猜测，也不允许换工具绕过 |
| Pi/DSH 已记录 prompt_attempted 且没有终态结果 | 显示 OUTCOME_UNKNOWN；只有正面发送尝试才分类，不新增可重发凭据 |
| 指定自测有匹配的原生完成事件、整数退出码 0 且 ok=true | 自测通过；不等于独立验收 |
| 指定自测最终匹配事件为非零退出码 | 保留验证失败，执行阶段与验证阶段分别展示 |
| schema=2 原生任务正常结束，但指定命令没有匹配证据 | 执行 completed、自测 verified=false、TEST_UNCONFIRMED；不声称自测成功或原生执行失败 |
| schema=1/legacy 或历史自建工具模式缺少指定自测证据 | 保留既有严格失败规则，不静默升级 |
| 会话关闭或控制器收尾未确认 | 保留失败/待收尾及已有成果，不把生成结果丢掉，也不自动重发 |

WorkBuddy/ZCode 共享 native_selftest 判断；只有匹配的已完成终端事件可提供证据。普通语句改写、分组和格式差异仍不能直接升级成测试通过；诊断哈希仅供说明。新任务不再把“没有精确匹配”直接等同“原生执行失败”，主脑需独立验证；验收摘要保留 verified=false，接受时必须附逐项独立证据和说明。不会自动验收或追认旧失败。

Pi/DSH 默认不指定 test_command 时仍由原生 Agent 自主自测；显式 test_command 保留已有控制器测试路径，不宣称四端自测底层实现已完全相同。新的发送尝试标识不是证明未发送的证书，DSH/Pi resend 契约仍由原控制器认领及显式恢复负责。保护 proof 丢失或畸形保持验证不足；未验证所有 IO 故障与所有原生宿主权限码。

正式状态/交付和两宿主工作台共用同一执行结果投影。组件将问题行标为“需关注”，与执行状态、自测、会话收尾和独立验收并列，保留全部已记录问题。

## 成果统计

隔离 Git 任务在控制器收尾时按基线和实际成果提交生成清单，辅助业务文件不会因未列入 files 而漏掉。临时目录/控制器材料保持提交排除；敏感材料不读取正文或计算内容哈希，列为未核实。

长期维护的回归测试属于正常业务成果，应放在正常源码/测试目录；只有一次性诊断脚本与运行产物放入任务临时目录。WorkBuddy/ZCode 共用该提示，不再把所有“测试脚本”一概引向不进入成果提交的目录。用户明确指定的交付路径优先，已有文件权限与临时目录排除规则不改变。

清单只覆盖提交中的业务改动，不包含忽略文件或授权的外部路径。非隔离/非 Git 场景仍以预期文件核对为主，界面明确显示统计不完整，清单为空不能证明没有任何改动。成果清单和执行器自测都不能替代独立验收。

## 生效与验证边界

本批不改用户开关、访问模式、预算、并发数、模型或账户，不创建系统隔离、不退出桌面程序、不部署或推送。四端源码、模拟工具/HTTP/浏览器、安装 CLI 接本地模拟提供方和真实账户验收分别记；运行版升级与原生 GUI 另验。
